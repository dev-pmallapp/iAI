### 1. `binding.unitOfWork` is one object of five prose strings, not a collection

CLAIM-47.1 opens *"one sub-issue per `binding.unitOfWork` item"*. There is no
item.

`packages/core/src/binding/domain.ts:111-117` declares `UnitSpec` as five
`readonly string` fields — `noun`, `description`, `minSize`, `maxSize`,
`leafSkill` — and `:225` declares the field as `unitOfWork: UnitSpec`,
**singular**. `packages/core/src/binding/validate.ts:70-76` validates it with
`isPlainObject`, not `Array.isArray`. **`for (const item of binding.unitOfWork)`
is a TypeError.**

It is a *definition of what one unit is*, not an *enumeration of the units in
this Story*. And it carries the same defect handoff finding 11 records for
`size`, which `packages/core/src/binding/domain.ts:102-110` states in terms:
*"the declared type is a sentence… `size` is MODEL-JUDGED against a written
bound, not tool-checked against a number."* `unitOfWork` inherits that **and
adds a categorical one** — `size` at least has a value to judge; `unitOfWork`
as CLAIM-47.1 uses it has no referent at all.

**There is also no binding to read.** All five domain packages are 5-line stubs
exporting `{ id }` and nothing else. The only real `DomainBinding` in the tree
is `nullBinding` in `packages/domain-null/src/index.ts:33-47`, whose `noun` is
`"nothing"`.

**The real enumeration source is the Design's `## Build Targets` table**, and
four independent sources say so:

| Source | Says |
|---|---|
| `references/design-format.md:117-126` | `## Build Targets` is *"authoritative over the milestone's indicative task table… so `/iai:task-create` cannot silently drop it"* |
| `packages/core/src/guards/design-spine.ts:47-58` | `"Build Targets"` is member 8 of the enforced ten-section spine — **every Design already has one** |
| `docs/design/04-domain-dev.md:442-450` | the worked example produces *"one Task per build target"* |
| the issue body itself | *"The authoritative list is produced by `/iai:task-create` from the Build Targets table in this Story's Design"* — **which contradicts the claim eleven lines above it** |

`docs/design/01-skill-hierarchy.md:96` and `docs/design/03-workflow.md:19` both
say *"one sub-issue per unit of work"* — the general phrase. **Only CLAIM-47.1
turns that into a field read.** `binding.unitOfWork` supplies the **noun and the
sizing bound used to judge the table**, and nothing more.

### 3. Cycle detection does not exist, and the plural contradicts a shipped anti-claim

CLAIM-47.2 has two halves and both fail.

**The cycle half has no foundation whatsoever.** Searched across every `.ts`,
`.md`, `.py` and `.sh`: no topological sort, no visited set, no adjacency
structure, no `Graph`/`Node`/`Edge` type. Every match for `cycl` is either
`lifecycle` or the NEVER-31.8 *cyclic-object* fuzz corpus.

Worse, **the edge itself is never read.** `Blocked by:` has exactly one producer
— `packages/core/src/gh/pr.ts:339`, inside `renderPrBody` — and **no parser
anywhere**. The precedent for the missing half exists and was deliberately not
extended: `sub-issues.ts:132` defines `PARENT_LINE_RE` and `:150`
`findParentInBody` for the sibling `Parent:` line. **You cannot detect a cycle
in edges nobody reads.**

**The plural half contradicts a ruled decision.** CLAIM-47.2 says
*"`Blocked by: #N` **lines**"*. `pr.ts:336-339` emits **exactly one
comma-joined line**, and that is Decision 8 of `docs/design/stories/21.md:213`
— *"`Closes` is per-line; `Blocked by:` is comma-separated"* — pinned by
`packages/core/test/gh-pr.test.ts:171-201` and by NEVER-21.7. **A skill emitting
one line per blocker would violate a shipped anti-claim.**

Two further gaps: `renderPrBody` builds **PR** bodies, while every worked
example puts `Blocked by:` in the **issue** body
(`docs/design/04-domain-dev.md:449`, `docs/design/05-domain-trading.md:525`),
and no issue-body builder exists. And *"rather than partially created"* requires
transactional rollback across N `gh issue create` calls;
`packages/core/src/gh/resume.ts:131` resumes a partial batch, it does not undo
one.

**The salvageable core is the ordering clause, and it is already load-bearing.**
`sub-issues.ts:200-203` refuses to sort, in a comment that names this claim two
milestones early: *"`docs/milestones/M2.md:123-125` requires `Blocked by:` lines
to match the parent checklist order, so sorting here would silently break a
claim two milestones away."*

## Vision

Three Tier-1 verbs that close the loop from a Design to a merged, evidenced,
explicitly-closed task — and that are honest at every point where the
repository cannot yet check them.

`task-create` reads the **Design's `## Build Targets` table**, judges it against
`binding.unitOfWork`'s noun and prose bounds, and opens one sub-issue per row —
each labelled, each anchored to a real claim, each parented on whichever of the
two paths the capability probe reports, and **each leaving the Story's existing
body intact** because a merger exists that today does not.

`task-do` cuts a branch from the story branch **or the previous task branch**,
commits under the validated prefix, and opens a draft PR that the argv layer
already refuses to point at the default branch.

`task-verify` writes an artifact at a path that renders — `{issue}`, not `{n}` —
posts its sentinel through the idempotent upsert, marks the PR ready and
**re-reads to confirm it took**, transitions the label in one command, and
closes explicitly at the point the Design rules is correct.

All three declare a `## Re-entry` table in which every mutating step is preceded
by the read that makes it idempotent — the restatement `CLAIM-41.8` established
and #293 will eventually discharge.

## Decisions

Recommendations pending the gate. `docs/design/03-workflow.md:271`.

### Decision 1 — CLAIM-47.1 reads the Design's `## Build Targets`, and a merger is built

**Recommended: restate.** `binding.unitOfWork` is `UnitSpec` — one object of
five prose strings, validated as `isPlainObject`. It has no items. Four sources
name `## Build Targets` as the real enumeration, **including the issue body
eleven lines below the claim that contradicts it**, and the spine guard already
guarantees every Design has one.

`binding.unitOfWork` is not discarded: it supplies the **noun** and the prose
sizing bound the table is judged against, which is exactly what
`docs/design/01-skill-hierarchy.md:96` gives `task-create` to read.

**And the destructive checklist path is fixed here rather than inherited.**
This is a live defect in shipped code, found by implementing rather than by
review, and its test asserts the four argv elements it cannot get wrong while
never checking the one thing that matters.

### Decision 2 — CLAIM-47.2 keeps the ordering, drops the plural, and names an owner for cycles

**Recommended: restate, and refuse to build cycle detection here.** The plural
form contradicts NEVER-21.7 and Decision 8 of `docs/design/stories/21.md:213`;
implementing it as written would break a shipped anti-claim to satisfy a seeded
one.

Cycle detection has **no foundation at all** — no graph code, and the dependency
edge is emit-only with no parser, though the sibling `Parent:` line has both.
Building a parser, a graph and a refusal is a multi-target project inside a
clause. **It gets an owner and an issue, not a sentence in a skill body.**

The ordering clause survives intact and is already enforced by a comment that
named this claim two milestones early.

### Decision 3 — CLAIM-47.3 is widened, not narrowed

**Recommended: widen to "the story branch or the previous task branch".** The
claim as seeded forbids the stacking shape
`references/branch-and-pr-model.md:15` mandates and `:19-34` depends on for
merge order. A skill implementing the claim literally would refuse the
repository's own workflow.

Note what is already done: the default-branch refusal, the unconditional
`--draft`, and the `Closes`-refusal all shipped in S1.3, in code whose comments
cite `docs/milestones/M2.md:126-128` by line. **This is the first seeded clause
in M2 that was built before its Story existed**, and it is worth recording as
the counter-example to the five-Story pattern of under-counted enforcement.

### Decision 4 — CLAIM-47.4 inherits, and may not be upgraded

**Recommended: inherit `CLAIM-41.8`'s restatement verbatim.**
`docs/design/stories/41.md:564-565` — *"S2.3, S2.4 and S2.5 inherit
`CLAIM-41.8`'s restatement until #293 lands"* — ruled at the S2.2 gate (G4).

#293's Design names `CLAIM-47.4` **by number** in its own Out of Scope, and its
gate question G2 asks a human to forbid the upgrade explicitly. **This Story must not pre-empt that ruling in either direction.**
The three `## Re-entry` tables are the evidence, and the denominator — one
artifact row per table row — is tool-checked even though the verdict is not.

### Decision 5 — CLAIM-47.5 is restated three ways, and one contradiction goes to the gate

**Recommended: `{issue}` not `{n}`; conditional `--remove-label`; and rule the
closure timing.**

The first two are forced. `packages/core/src/evidence/template.ts` refuses `{n}`
at construction and its error message names `docs/milestones/M2.md:132` — this
claim — as defective. The `--remove-label` pairing is the **second occurrence**
of a defect `labels.ts:16-26` already restated for CLAIM-21.3, in that file's
own comment; restating it the same way is consistency, not novelty.

**The third is a genuine contradiction and needs a human.** CLAIM-47.5 closes
at verify time; `references/gh-operations.md:56` and
`references/branch-and-pr-model.md:53` both say *after merge, citing the merge
commit*. A human merges. Verify-time closure means closing an issue whose PR is
unmerged; after-merge closure means `task-verify` cannot complete its own claim.
**Gate question G3.**

### Decision 6 — the git layer is shared with #293, not built twice

**Recommended: one git/argv execution layer, owned by whichever Story lands
first, consumed by the other.** #293's Build Target 1 is an adapter port from a
`readonly string[]` to a process. This Story's Build Target 6 needs git argv
executed. **They are the same seam.**

Two ports is the duplicate-contract defect arriving before either exists —
exactly the shape of `scripts/bootstrap-github.sh` hand-writing argv that
`packages/core/src/gh/milestones.ts` already builds, which #293's Design
records. **Ruling it now costs one gate question; reconciling two ports later
costs a Story.** Gate question G4.

> **#293's Design is cited by issue number, never by path.** The two Stories
> are independent and may merge in either order; a path citation would make
> this Design fail `path-dangling` on any branch where the other has not
> landed. The precedent is finding 38 — de-path the name in the prose.
