# S1.3 — GitHub operations layer

**Story:** #21 · **Milestone:** M1 — Kernel and foundation
**Unit of work:** one `gh` operation family
**Creates:** `packages/core/src/gh`
**Widens:** `scripts/lint.ts` (purity scope), `packages/core/src/index.ts` (barrel)

Every `gh` invocation iAI will ever make is constructed here as an argv array and
parsed here from a response value. Nothing in this directory executes anything.
That is what lets the whole GitHub surface be tested without a network, a token
or a repository.

---

## Problem

S1.2 could be written against a design document that was merely *inconsistent*.
S1.3 cannot: three of its six seeded claims describe behaviour that **no
document in this repository specifies at all**. This Design's main job is to say
which of those it authors, on what basis, and where it is guessing.

**1. The exit-code taxonomy does not exist.** `CLAIM-21.6`
(`docs/milestones/M1.md:140-141`) requires that "every `gh` exit code in the
taxonomy has a fixture and is classified retryable or fatal". No `gh` exit code
is named anywhere in this repository. The only pointer is
`docs/design/01-skill-hierarchy.md:55`, which assigns the taxonomy to
`references/gh-error-handling.md` — a file that does not exist and is
allow-listed as M2 work at `packages/core/src/guards/path-allowlist.ts`. The
milestone's own task table closes the loop: S1.3 "feeds
`references/gh-error-handling.md` in M2" (`docs/milestones/M1.md:149`). **S1.3
authors the taxonomy from zero.** That is a licence to invent, and Risk 7 of
`PLAN.md` names invention by an agent as a live failure mode. Decision 3 is how
this Story constrains itself.

**2. A pure module is required to read an HTTP response header.**
`CLAIM-21.5` (`docs/milestones/M1.md:137`) begins "Given a `403` with
`x-ratelimit-remaining: 0`". Both tokens appear exactly once in the repository —
in that claim. `ARCHITECTURE.md:90` requires `gh/` to "never shell out itself",
so the header cannot be fetched; it has to arrive. No document says in what.

**3. The capability probe is stateful, and this directory cannot hold state.**
`docs/design/04-domain-dev.md:504` says the sub-issue capability "is probed once
per session and cached, not retried per Task". A probe is I/O and a cache is
session state. Neither is available to a pure constructor. The same shape
recurs at `docs/design/03-workflow.md:225`, where a no-op label transition is
"skipped after reading current labels" — another read this layer cannot perform.

**4. `CLAIM-21.3` contradicts the workflow document it implements.** The claim
requires "exactly one `gh issue edit` carrying **both** `--add-label` and
`--remove-label`" (`docs/milestones/M1.md:133-134`).
`docs/design/03-workflow.md:224` says the opposite for a real case: "For an issue
entering its first status, the `--remove-label` is simply omitted." Read
literally the claim makes the first transition of every issue's life either
unsatisfiable or a lie.

**5. Two body directives, opposite list rules, and a claim that would break
one.** `Closes` must be one per line (`docs/design/03-workflow.md:320-322`;
`CONTRIBUTING.md:336`), and `docs/milestones/M1.md:148` says "comma-separated
lists are rejected at construction". But `Blocked by: #931, #932`
(`docs/design/04-domain-dev.md:449`) is comma-separated and correct. A generic
comma rejection breaks it.

**6. `gh issue view --json parent` is not a field.**
`docs/design/01-skill-hierarchy.md:434` still uses it. The reconciliation pass
already caught this and recorded the verdict `corrected`
(`docs/design/verification-pass.md:246`); the correction was never applied at
source, and the valid form sits eleven lines earlier in the same document at
`docs/design/01-skill-hierarchy.md:411`.

## Vision

A caller says *what* it wants done. This layer answers with an argv array and,
given the result of running it, a parsed value or a typed failure. The whole
surface is a set of total functions over plain data, so the test suite is a
golden-argv corpus and a response-fixture corpus, and neither needs a token.

The adapters keep the only thing they should have: the act of running a process.

## Out of Scope

- **Executing anything.** No `child_process`, no `Bun.$`, no `fetch`, no `gh`.
  `CLAIM-21.1` states this as a claim; `NEVER-21.9` states it as a prohibition,
  and the lint rule of Decision 9 is what makes it enforceable.
- **Deciding *which* comment to write, or whether to update one.**
  `docs/design/01-skill-hierarchy.md:54` lists "comment upsert by sentinel"
  among the operations this layer's downstream reference document owns, while
  `docs/milestones/M1.md:187` assigns "idempotent comment upsert keyed by
  sentinel" to **S1.4**. Decision 10 draws the boundary: S1.3 constructs the
  create-comment and edit-comment argv; S1.4 owns sentinel discovery and the
  upsert decision that chooses between them.
- **Reading the issue tree back.** `docs/design/04-domain-dev.md:504` says
  `status` "derives the tree" from `Parent:` lines and the parent checklist in
  fallback mode. `status` is a Tier-1 M2 skill
  (`docs/design/01-skill-hierarchy.md:106`). S1.3 owns the shapes it must
  produce, not the derivation.
- **Writing `references/gh-operations.md` or `references/gh-error-handling.md`.**
  Both are M2. This Story produces the behaviour those documents will describe;
  `docs/milestones/M1.md:149` says so explicitly.
- **The retry loop itself.** This layer classifies a failure and can produce a
  plan. Sleeping, counting attempts and re-invoking are the adapter's, because
  all three are effects.
- **Resolving `owner/repo` from git.** That is Phase 0 context discovery, and
  `docs/milestones/M4.md:74-76` owns it. S1.3 accepts a repo as an input
  (Decision 6).

## Constraints

- **Purity, at the same standard as S1.2.** No I/O, no `process.cwd()`, no
  Bun globals, no node builtin import. `CLAIM-15.6`'s harness and the
  `no-io-in-pure-modules` rule both exist; today neither covers this directory
  (Decision 9).
- **Never scrape human-formatted output.** `docs/design/09-security.md:192`:
  "Use `gh` with `--json` and parse; never scrape human-formatted output."
  Decision 7 records the one place that rule cannot be honoured and what is done
  instead.
- **`gh pr merge` is not constructible.** `docs/design/04-domain-dev.md:250`
  denies it to iAI and `docs/design/09-security.md:357` puts it on the bash
  deny-list. A layer that can build every `gh` call must be unable to build
  that one. `NEVER-21.10`.
- **Fail closed.** An unmapped exit code is fatal, never retried
  (`docs/milestones/M1.md:140-141`). An unrecognised response shape is a parse
  failure, not a permissive default.
- **Total functions.** No constructor throws on hostile input; malformed input
  returns a typed failure. Same posture as `checkEgress` under
  `NEVER-15.8`.

## Dependencies

`Decision` and the `decide` helper from `packages/core/src/decision.ts`, shipped
by S1.2 and merged. Nothing else. S1.3 is explicitly parallel with S1.2 and S1.4
— `docs/milestones/M1.md:272-274` notes the three touch disjoint directories and
share only the `Decision` type.

**Downstream.** M2 cannot begin its reference documents until this Story and
S1.4 merge, because those documents "document behaviour that must already exist
rather than behaviour someone intends to build".

## Goal

Every `gh` call iAI makes is a value produced by a pure function, every failure
mode it can encounter is classified, and no path in the directory can execute a
process.

### Decision 1 — the response envelope is an input value

`CLAIM-21.5` needs a status code and a header. `CLAIM-21.4` needs the issue's
current labels. `CLAIM-21.2` needs to know whether the sub-issue API is present.
None of the three can be fetched from inside this directory.

All three arrive the same way: as a plain value the caller already holds. The
adapter runs the process, captures exit code, stdout, stderr and — where it
used `gh api` — the response headers, and hands that envelope back in. The core
classifies it.

This is not a new pattern. Decision 1 of `docs/design/stories/15.md` faced the
identical problem with consent and settled it the same way: *a value handed in
by the caller, never a lookup*, because a lookup is I/O and I/O is forbidden.
Reusing that shape keeps one rule in the kernel instead of two.

It has a cost worth naming. The header the planner needs is only available if
the adapter asked for it, and `gh api --include` appears nowhere in this
repository today. **The envelope's header map is therefore optional, and a
missing header must classify conservatively rather than optimistically** — an
absent `x-ratelimit-remaining` on a `403` is treated as *possibly* rate-limited
and yields a plan, because the alternative is to treat a real rate-limit as a
fatal error and abandon a batch.

### Decision 2 — the first-status carve-out

`CLAIM-21.3` and `docs/design/03-workflow.md:224` cannot both be satisfied
literally. One of them has to be read narrowly, and the choice is not arbitrary:
the invariant the workflow document is protecting is stated at
`docs/design/03-workflow.md:167-169` — "**Every transition is a single
command.** … so there is no window where the issue has zero or two statuses."

That invariant is about **atomicity**, not about the presence of two flags.
An issue entering its first status has nothing to remove; emitting
`--remove-label` for a label that is not there would be a fabricated argument,
and `gh` would be asked to remove something that does not exist.

So `CLAIM-21.3` is read as governing the transition-with-a-predecessor case,
which is what "transition" means everywhere else in the tree, and the
first-status case emits a single command with `--add-label` alone. **Both cases
emit exactly one command, which is the property the claim exists to protect.**
The claim text above is written to say this rather than to be corrected later.

### Decision 3 — the taxonomy is authored, and its provenance is marked

There is no `gh` exit-code taxonomy in this repository to implement. Writing one
from imagination is precisely the failure Risk 7 of `PLAN.md` warns about, and
`docs/design/verification-pass.md` exists because that failure already happened
once at scale.

Two constraints make this safe enough to proceed:

1. **Every entry carries a provenance marker.** `observed` means the code and
   its meaning were confirmed against the `gh` binary on the machine, with the
   version recorded. `assumed` means it is reasoned from GitHub's documented
   HTTP semantics and has no local confirmation. The verification task records
   the `gh` version, exactly as #198 did when it confirmed a row against a
   shipped binary rather than against the build an issue named.
2. **The default is fatal.** `docs/milestones/M1.md:140-141` already requires
   an unmapped code to be fatal and not retried. So an incomplete taxonomy
   degrades to "stop", never to "retry forever". A missing entry costs a halted
   batch, not a runaway.

M2's `references/gh-error-handling.md` inherits the table with its markers
intact, so the `assumed` rows are visible to whoever writes it rather than
laundered into fact by being copied.

### Decision 5 — the fallback shapes, and the form that is dropped

No document in the tree shows one line of the `## Tasks` checklist, and the
`Parent: #N` line's position, column and uniqueness are unspecified — in sharp
contrast with the sentinel producer rules at
`docs/design/03-workflow.md:388-394`, which pin exactly those properties.

The only working emission is `scripts/bootstrap-stories.py`, which produced the
issue tree this repository is currently running on. It is adopted as the
precedent, with the shapes pinned here so they stop being implicit:

- `Parent: #N` sits at column zero on its own line, exactly once per task body.
- The parent's checklist sits under an H2 that is exactly `## Tasks`.
- Checklist order is significant, because `docs/milestones/M2.md:123-125`
  requires `Blocked by:` lines to match "the parent checklist order".

**One thing in that script is deliberately not adopted.** It degrades to
`Parent: the S1.1 Story` when the parent number is unknown. A body link whose
whole purpose is machine-readable parenting must not have a prose form — that
is a link that silently stops being a link. Here, an unknown parent is a
construction failure, not a degraded string.

### Decision 7 — the one place scraping is sanctioned

`docs/design/09-security.md:192` forbids scraping human-formatted output. But
`gh issue create` has no `--json` flag, and the number of the issue it just
created is available only in the URL it prints. `scripts/bootstrap-stories.py`
recovers it by splitting that URL. No document acknowledges the conflict.

The rule wins everywhere it can be honoured, and this is the single exception.
It is contained rather than spread:

- Exactly one parser is permitted to read unstructured `gh` stdout, and it does
  nothing but extract a trailing issue number from a URL.
- It validates: a line that is not a GitHub issue URL is a typed failure, not a
  guessed integer.
- Every other operation uses `--json` and a structured parser.

Recording it here means a future reader finds a decision rather than a
violation, and M2's reference document inherits a known exception instead of
discovering an inconsistency.

### Decision 9 — the lint gap is closed in this Story

`no-io-in-pure-modules` matches only the path segments `classify` and `guards`;
its user-visible scope string at `scripts/lint.ts:425` says so. Any file under
`packages/core/src/gh` could import `node:child_process`, call `Bun.$` and call
`fetch` today with **zero** violations.

`CLAIM-21.1`'s three banned tokens map one-for-one onto detections the rule
already implements, so this is a scope widening and not a new rule. The same
applies to `packages/core/test/purity.test.ts`, which imports only the
`classify` and `guards` barrels and would not exercise this directory either.

Leaving either to a follow-up would ship a claim whose enforcement does not
exist, which is the exact shape of the weakness recorded against `skill-lint` —
a rule that polices nothing and is not obviously doing so. `NEVER-21.9` makes
the coverage itself a verified property rather than an assumption.

### Not resolved here, and deliberately

- **`gh issue view --json parent` at `docs/design/01-skill-hierarchy.md:434`.**
  This layer will not model a `parent` field, because there is not one. Editing
  that document is a documentation fix in someone else's Story; the verdict is
  already recorded at `docs/design/verification-pass.md:246` and re-recording it
  here would not make it land.
- **The `S1.3` label collision** between #21 and #194, open as #209. The header
  block above carries `**Story:** #21` to disambiguate. Consistent with #194 and
  #226, which both declined to fix it.
- **Graph equivalence.** `docs/milestones/M1.md:147` requires the fallback to
  "produce an equivalent issue graph" and no document defines equivalence.
  S1.3 pins the shapes it emits; whether a reader reconstructs the same tree is
  `status`'s claim to make in M2, and asserting it here would be asserting
  something this Story cannot observe.
