# S2.6 — Skill execution harness

**Story:** #293 · **Milestone:** M2 — Universal lifecycle
**Unit of work:** one build target
**Creates:** the adapter port — the first code in this repository that executes anything a skill decides
**Widens:** `ARCHITECTURE.md` (one Build Targets row), `.github/workflows/ci.yml` (one job)
**Corrects:** `docs/milestones/M2.md` (the re-run verification sentence, and a build-target assignment that names a `docs` target)

S2.1's difficulty was that four of its six claims governed a population it did
not create. S2.2's was that five of its six seeded claims were false at HEAD.
**S2.6's is that the thing it is asked to verify cannot be verified by the
architecture it is asked to verify it with, and saying so precisely is most of
the work.**

The milestone asks for "each skill runs twice and the second run makes zero
mutations". That sentence contains an execution, and **nothing in this
repository executes anything**. It also contains a population — *the skill* —
and every cheap way to build the harness silently substitutes a different one.
This Story is where that substitution gets named, priced, and either accepted
out loud or refused.

### 2. The port that four contract documents assign work to does not exist

`packages/core/src/gh/` is **12 files, 2120 lines, and provably pure** — zero
imports leave the directory, enforced three independent ways (static lint,
mutation test, runtime trap). `ARCHITECTURE.md:82` states the doctrine: *"No
host imports. No `process.cwd()`. Everything is a pure function from input to a
decision object that an adapter applies."*

**No adapter applies it.** Four contract documents assign execution to an
adapter — `references/gh-operations.md`, `references/gh-error-handling.md`,
`ARCHITECTURE.md`, and `docs/design/08-dual-target.md` — and the two adapter
packages are 25 and 20 lines of pure `Decision` → exit-code mapping, put out of
scope by `docs/design/stories/9.md`.

So **no `gh` argv this repository has ever built has ever been executed.** Six
operation families have been tested against golden argv only. The S2.1
precedent is exact and expensive: `references/verification.md` records a
required check that shipped with sixty passing tests and rejected 7 of 9 real
verbs on first contact. **That bill arrives here**, and it is the strongest
justification for the L sizing.

**There is no single choke point to intercept.** The literal `"gh"` appears as
`argv[0]` at **22 sites across 6 modules**; there is no `ghCommand()` factory.
The widest partial choke point is `ghOk()` (38 call sites, but generic over its
payload); `repoFlag` (14 sites) plus `repoApiPath` (5 sites) still miss the
GraphQL sub-issue mutation, which takes two node ids and no repo at all.

The **type-level** choke point already exists and is the answer: every mutating
command leaves this layer as a `readonly string[]`. Whatever consumes one is
the true single choke point — and it does not exist yet. **The recorder can
therefore be designed into the executor rather than retrofitted around it.**

### 3. "Live versus replay" is a projection of a three-axis space, and the axis that matters is not the one named

Decision 6 of `docs/design/stories/41.md` poses the question this Story must
answer first:

> a replayed transcript proves the *recording* is stable; it cannot detect that
> a skill would issue a second `gh issue create` on a real second run, because
> the recording never made the first one.

**That sentence is exactly right, and it is not the whole space.** There are
three independent axes:

| Axis | Question | Values |
|---|---|---|
| **A — the oracle** | what supplies the skill's *decisions* | live model · recorded token stream · recorded tool-call cassette · a hand-written procedure |
| **B — the world** | what the skill *acts on* | real forge · local git fixture plus a stateful fake forge · nothing, argv inspected only |
| **C — sequencing** | from what state run 2 starts | one run · run 2 from run 1's state · run 2 from clean state |

**Idempotency is a `(B, C)` property.** It is `f(f(s)) = f(s)` over repository
state. Axis A decides *whose* `f` is under test; it does not decide whether
`f∘f` is under test at all. Decision 6's sentence is precisely true of *token
replay against no world from a clean state*, and says nothing about *any oracle
against a stateful world from run 1's state*.

That is why the candidate set is eight, not two, and why the recommendation
below splits along B and C rather than along A.

### 4. Removing the model does not buy the same verification more cheaply — it buys a different claim about a different population

This is the load-bearing finding, and it must not be softened.

A harness with no model executes **a procedure a human wrote by reading the
`SKILL.md`**. It proves that *that procedure* is idempotent. It does not prove
that **the model reading `skills/story-create/SKILL.md`** implements that
procedure. The harness's transcription and the markdown are two artifacts, and
their agreement is *meaning*, not *mechanism*.

**This is the category error at its fifth occurrence**: a rule pointed at a
population that does not have the property it describes. Plan amendments 1, 3
and 5 were the first three; `CLAIM-41.5` was the fourth, and it landed **inside
a gate-approved claim** — which is #307, still open. A fifth landing inside
#293's own claims is the predictable failure, and this Story's job is to make it
impossible rather than unlikely.

**It is not detectable by mutation testing.** Perturbing the harness's procedure
will kill mutations beautifully. Perturbing a `SKILL.md` will kill **nothing**,
because the harness never reads it as an oracle. That asymmetry is itself
measurable, and `NEVER-293.5` below turns it into a published number instead of
a footnote.

### 5. A fake forge that always answers correctly cannot exercise the failure the skills were written to survive

Measured over the four bodies on disk: **4 of 4 name a rate-limited-read-as-
absence hazard, and 4 of 4 name a partial-write hazard.** `story-create` states
it loudest — a rate-limited read treated as "no Stories exist" is *"the single
most damaging failure mode of this skill"*, because absence is what every create
step keys on.

A fixture forge that is always honest is **a check that cannot meaningfully
fail** — which is `ci.yml:137-146`'s own stated disqualifier for making
`smoke-install` required.

The mirror-image defect is worse because it passes. GitHub's milestone endpoint
returns 422 on a duplicate title, and `goal-create` uses the milestone title as
its identity key. **If the fake enforces that, the second run makes no mutation
because the fake refused it — not because the skill declined to try.** That is
a guard shadowed by another guard, one layer out: **a skill shadowed by its own
test double.** The remedy generalises identically — record the *attempted*
mutating argv, not the successful one, and make the fake permissive exactly
where GitHub is permissive.

### 6. There are two mutation surfaces, and an argv-only recorder silently excludes half the skills

| Surface | Who mutates it | Detected by |
|---|---|---|
| the forge | all four skills — milestone, issues, sentinel comments | mutating-argv classifier |
| the git worktree | `story-design` writes a Design; `story-test-plan` writes a plan; both commit | worktree tree hash |

An argv-only recorder scores a Design rewritten with **identical bytes** as zero
mutations. That is wrong twice: it is an action that can race, and it means the
"zero mutations" denominator quietly covers two of four skills.

### 7. Four constraints that are structural, not preferences

**7a. A live check can never be a required CI check.** `.github/workflows/ci.yml:8-25`
implements NEVER-9.8 and forbids exactly the two escapes a live job would need:
a required job may never carry an `if:` (a skipped job reports **success**), and
the file may carry no `paths:` filter (a filtered workflow leaves required
checks pending forever). Add that `pull_request` from a fork receives no
secrets, and a required live job is **structurally illegal**, not merely
expensive.

**7b. M2 cannot exit without at least one live run.** `docs/milestones/M2.md:240-241`
is an exit criterion: *"Measured token cost of Tier 0 plus one Tier-1 verb is
recorded in the evidence artifact."* **A token cost is a property of a live
model call.** There is no non-live way to measure it. This is a pre-existing
commitment, not a preference — and with 7a it means **one architecture cannot
satisfy both**.

**7c. The harness cannot live in the pure kernel.** `ARCHITECTURE.md:82`
forbids host imports and `process.cwd()` there. A harness that spawns processes
and mutates a worktree is the antithesis. Note the trap: a sixth directory under
`core/src` would escape the *lint rule*, whose scope is five named directories,
while violating the *doctrine*.

**7d. The milestone assigns executable work to a documentation target.**
`docs/milestones/M2.md:105` assigns the harness to `iai-skills`, which
`ARCHITECTURE.md:69` and `:73` declare a `docs` target with **no build file**,
*"validated by the frontmatter linter rather than compiled."*
`references/context-discovery.md` is explicit that a target absent from that
table does not exist for planning purposes. **This is a Build Target the
milestone does not list — the sixth consecutive Story where that is true.**

### 8. `goal-create` has no public Phase-0 input, and this is recorded nowhere

`goal-create`'s input is a goals source under `USER/`, which
`references/data-classification.md:66-76` establishes is **a gitignored symlink
into a separate private repository**, and where *"an unclassified file under
`USER/` is treated as `PRIVATE`, never as `INTERNAL`"*.

Two consequences, neither previously raised:

1. **No public checkout can supply `goal-create`'s Phase-0 input.** Its
   scenarios are blocked on **#292** unless this Story supplies its own goals
   fixture and declares it `synthetic` with the reason. `docs/design/stories/41.md`
   states #292 does not block S2.2; it says nothing about #293.
2. **A live run of `goal-create` against the real goals source on a cloud model
   is a designed egress violation.** `PRIVATE` never reaches a cloud model — no
   consent, no de-identification, no override. This is a `NEVER` claim, not a
   footnote, and it is `NEVER-293.10`.

### 9. Two pre-existing defects this Story will make visible

**9a.** `scripts/bootstrap-github.sh` hand-writes the exact argv that
`packages/core/src/gh/milestones.ts` builds, twice — the milestone list and the
milestone create. Two implementations of one contract, neither aware of the
other. Invisible today because nothing executes the builders; visible the moment
the port exists.

**9b.** `docs/milestones/M2.md:230-232` still carries the **bare-token**
domain-agnosticism exit criterion that gate ruling G2 overturned in favour of

say whether it fixes this or records why not. **Milestone edits must be
line-neutral** — roughly thirty citations index `M2.md` positionally and two of
them are in immutable evidence artifacts.

## Vision

An adapter port exists: one interface from a `readonly string[]` to a process
result, with two implementations — a real one that runs `gh`, and a fake forge
that serves a stateful, deliberately fallible GitHub. Every mutating command in
the system flows through it, because it is the only route from the pure kernel
to a process.

Around it, a fixture repository seeds a real local git tree per scenario, and a
mutation recorder captures **both** surfaces — attempted mutating argv, and the
worktree tree hash. A scenario runs a skill twice. The runner asserts, in this
order and per scenario, that **run 1 mutated** and only then that **run 2 did
not** — and it exits non-zero if either denominator is empty.

That harness is deterministic, offline, secret-free, required in CI, and
demonstrably able to go red. It earns **new claims about the protocol and the
command layer**, and it is stated in the Design, in the plan, and in its own
output that **it does not test the model reading the markdown**.

Above it, a live rung runs the real skill on a real host against the same
fixture, never as a required check, once per Story that touches `skills/`. It
carries the measured token cost that M2's exit criterion needs, and its verdict
is `human-attested`, because n=1 over a non-deterministic function is an
existence proof, not a property.

The gap between the two rungs — *did the model follow the `SKILL.md`* — is
published as a number, not elided.

## Out of Scope

- **Token replay in every form.** Excluded by name, with the reason recorded, so
  that nobody restores it later believing it was an oversight. A fixed token
  stream **re-emits** decisions rather than re-deriving them; replayed against
  mutated state it re-issues the create by construction, which is a false red.
- **The tool-call cassette.** The near-miss worth naming: it is the only replay
  shape that could catch a genuine second create, because the model still
  decides and the cassette answers with post-mutation state. It dies on **tape
  invalidation** — the tapes expire on every `SKILL.md` edit, which is every
  Story in M2. Recorded here so the analysis is not redone.
- **Making the live rung a required check.** Structurally illegal under
  NEVER-9.8; pinned by `NEVER-293.10`.
- **Running the real `goal-create` against the real goals source.** Blocked on
  #292, and an egress violation on a cloud model regardless.
- **Upgrading `CLAIM-41.8`, `CLAIM-47.4`, or the S2.3–S2.5 inherited
  restatements.** Their population is the model reading the markdown. This
  Story does not test it, and Decision 2 says so.
- **M4/S4.5's end-to-end conformance suite.** `docs/milestones/M4.md:195` and
  `:215` own the milestone-to-merged-PR run. This Story builds the foundation
  that consumes.
- **Retiring `bootstrap-github.sh`'s duplicate argv** (Problem 9a). It becomes
  visible here; retiring it needs the bootstrap scripts reconciled, which is not
  this unit of work.

## Test Strategy

Denominators are stated because "zero mutations" over an unstated corpus is the
vacuous pass this repository has demonstrated daily since S1.3. **The governing
rule for this Story, and the single most important line in it:**

> **Every `== 0` assertion must be paired with a `> 0` assertion on the same
> counter, measured one run earlier.** "Run 2 made zero mutations" is meaningless
> alone. "Run 1 made more than zero **and** run 2 made zero" is the property.

## Decisions

Every decision below is a **recommendation pending the gate**. None is authored
here — `docs/design/03-workflow.md:271`.

### Decision 1 — two rungs, because one architecture cannot satisfy two structural constraints

**Recommended: a deterministic offline seam rung, required in CI; and a live
rung that is never a required check.**

Not a compromise — a consequence. `.github/workflows/ci.yml:8-25` makes a
required live check structurally illegal, and `docs/milestones/M2.md:240-241`
makes a live run mandatory for M2 to exit. The two constraints are both real and
both immovable, and no single architecture satisfies them.

The two rungs carry claims in two different classes, and **neither subsumes the
other**. The composition must be stated, or it is a lie by adjacency: the seam
rung's green does not imply the live rung's green.

### Decision 2 — the seam rung's green may not upgrade any inherited claim

**Recommended: NO, and say so in the Design, the plan, and the harness's own
output.**

This is the answer to the strongest argument against building the seam rung at
all, which is worth stating in full because it is correct:

> The seam harness verifies a re-implementation, and this repository will treat
> its green as if it verified the skill.

The mechanism is not hypothetical and every step has a precedent on disk. The
harness ships and reports four skills, zero mutations on the second run. Three
claims in S2.2's evidence are already marked *stated, not executed — needs
#293*. A later author reads the claim, sees a green harness, and upgrades
`CLAIM-41.8` from `model-judged` to `tool-checked`. Nothing catches it: mutation
testing cannot, and `claim-lint` checks that a class is one of three names, not
that the check supports it.

**The risk is manageable only if the gate closes it explicitly**, which is why
this is a gate question and not a note. `NEVER-293.5` is its mechanical half —
it publishes the size of the gap as a passing test whose PASS condition is that
the harness does **not** notice a mutated skill body.

> **Write the reason into that assertion's own comment.** The first person to
> read a green assertion over a mutated `SKILL.md` will "repair" it, and delete
> the only published measurement of the transcription gap.

### Decision 3 — the adapter port is the first build target

**Recommended: YES.** It is owed to the architecture by four contract documents
regardless of this Story; it is what makes both rungs possible; and it is where
the first-contact bill of Problem 2 lands. Sequencing it first surfaces the
defects in six `gh` families **before** anything is built on top of them.

It is also the honest justification for the **L** sizing, which the gate set
before this analysis existed.

### Decision 4 — the fixture repository is real git, and every denominator is asserted by the runner

**Recommended: YES to both halves.** A real local git tree, not a simulation —
the prior art already exists inline in one test, which builds, hooks, commits
to, and asserts non-mutation of a throwaway repository.

The assertion set is the house pattern applied to effect counts rather than
corpus sizes. **The scanning denominators stop the harness reporting success
over zero skills; only the `run1.mutations > 0` assertion stops it reporting
success over zero *work*.** A harness with the first and without the second is
`skill-lint`-green-over-zero-files with extra steps: it scans four skills,
executes nothing meaningful in either run, and reports a perfect result.

Two further mechanics are not negotiable. **The verdict is the exit code plus a
JSON artifact — the runner never greps its own stdout, and nothing greps the
runner's.** Finding 37 is exactly this: a mutation harness decided on
`"0 fail" not in stdout` and read a fixture's prose as the runner's verdict, and
its recorded owner is *"any future harness"* — which is this one. And the runner
must **exit non-zero on an empty roster**, with a test that invokes it against
one; `skill-lint` exits 0 over zero files today and its non-vacuity lives only
in a test file.

### Decision 5 — the fake forge must be able to lie, and must not enforce

**Recommended: YES to both, and they are separate requirements.**

Able to lie, because 4 of 4 skill bodies name a rate-limited-read hazard as
their damaging failure mode, and a fake that always answers correctly is a check
that cannot meaningfully fail. **Must not enforce**, because a fake that rejects
a duplicate title makes run 2 clean for the fake's reason rather than the
skill's — the test double shadowing its subject.

The remedy is the one S1.5 already paid for: **assert the reason, not the
verdict.** Record the *attempted* mutating argv, never only the successful one.

### Decision 6 — the recorder spans both surfaces

**Recommended: YES.** Argv and worktree, reported separately, with an
identical-bytes rewrite counted as a mutation. Each surface needs at least one
scenario that trips **only** it, so neither can be silently unwired — the shape
of mutation N2, where a scope entry was listed but never walked and four of five
assertions still passed.

Note the semantic model already in the tree: the plan type treats an empty
command list as a **successful** outcome, and the label transition already
returns "nothing to do" as success rather than as a failed create. That is the
zero-mutation result modelled as a first-class value, and the recorder should
mirror it rather than invent a second vocabulary.

### Not resolved here, and deliberately

- **The superseded bare-token exit criterion** at `docs/milestones/M2.md:230-232`
  (Problem 9b). An exit criterion contradicting a gate ruling. This Story opens
  the file for Build Target 10 and must state which way it goes; the resolution
  is not obviously this Story's.
- **`bootstrap-github.sh`'s duplicate `gh` argv** (Problem 9a). Visible the
  moment the port exists; retiring it needs the bootstrap scripts reconciled.
- **Whether M4/S4.5's fixture repository is this one.** Recommended at the gate
  as G6, because ruling it now is far cheaper than reconciling two later.
- **The stale-`:NN` guard, #304.** Sixth request. Every citation in this
  document was resolved by reading, which is the only reason it is trustworthy —
  and finding 32 records generating the defect twice in one task while actively
  watching for it. Diligence is demonstrably not sufficient.
