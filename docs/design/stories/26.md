# S1.4 — Evidence and sentinel engine

**Story:** #26 · **Milestone:** M1 — Kernel and foundation
**Unit of work:** one artifact surface
**Creates:** `packages/core/src/evidence`
**Widens:** `scripts/lint.ts` (purity scope), `packages/core/src/index.ts` (barrel)

A sentinel is how the pipeline finds its own history. This Story builds the
producer that writes one, the consumer that finds one, the linter that rejects a
malformed one, and the budget rule that decides whether the payload goes in the
comment or on disk behind a permalink. Nothing in this directory reads a comment
or writes a file — it decides, and hands the decision back.

---

## Problem

S1.3 found three claims describing behaviour no document specified. S1.4's
situation is the inverse and harder: the behaviour **is** specified, in
`docs/design/03-workflow.md:367-430`, and the milestone claims that restate it
have drifted from it in six places. Implementing `docs/milestones/M1.md`
literally and implementing `docs/design/03-workflow.md` literally produce
different engines.

**1. The claim under-specifies the linter by exactly one rule.**
`docs/design/03-workflow.md:388-392` defines **five** producer requirements.
`CLAIM-26.1` (`docs/milestones/M1.md:165-167`) says "first line of the comment
body, at column zero, unfenced, one per comment; the linter rejects each of
those **four** violations". The dropped rule is `docs/design/03-workflow.md:391`
— *"Exact | Lowercase, hyphenated, `##` heading level. `### iai-design` does not
match"* — the only one carrying case, hyphenation and heading level.
`docs/design/verification-pass.md:434` independently drops the same rule while
citing the range `:388-392` that contains it. A linter built to `CLAIM-26.1` as
written accepts `### iai-design` and `## IAI-Design`.

**2. `CLAIM-26.2` and `CLAIM-26.6` cannot both be true of the same surface.**
`CLAIM-26.2` (`docs/milestones/M1.md:168-169`) requires the consumer to
disambiguate "three `## iai-verdict` comments" by `createdAt`. `CLAIM-26.6`
(`docs/milestones/M1.md:177-179`) requires the producer to update "the existing
sentinel comment instead of posting a second", and
`docs/milestones/M1.md:191` requires that "a double producer run leaves exactly
one comment per sentinel". If the producer always upserts, three `## iai-verdict`
comments can never exist and `CLAIM-26.2` is untestable against real output.
Note that only `## iai-gate` carries an explicit one-comment rule
(`docs/design/03-workflow.md:270`); no document generalises it.

**3. "Summary rendering" is a named deliverable with no specification.**
`docs/milestones/M1.md:186` lists it as a build target and
`docs/milestones/M1.md:189` requires boundary fixtures to "produce the
documented strategies". The *strategies* are documented
(`docs/design/03-workflow.md:415-416`); the *rendering* is documented nowhere.
The only artifact resembling a specification is the illustrative block at
`docs/design/03-workflow.md:418-426`, which no document declares normative.

**4. The budget is measured on two different quantities.**
`docs/design/03-workflow.md:413` heads its decision column **"Artifact size"**.
`CLAIM-26.4` (`docs/milestones/M1.md:172-174`) mixes both in one sentence: "A
59,999-character *artifact* is inlined … no emitted *comment body* exceeds

Separately, `docs/design/03-workflow.md:415` defines `≤ 60000` as inline while
`CLAIM-26.4` names only 59,999 and 60,001 — yet
`docs/milestones/M1.md:189` demands a fixture at exactly 60,000.

**5. `{n}` is not a placeholder.** `docs/design/01-skill-hierarchy.md:229` says
"`{issue}` and `{ts}` interpolate", `CONTRIBUTING.md:66` defines `{issue}`, and
all six `EvidenceSpec` literals in the tree use `docs/evidence/{issue}-{ts}.md`.
But `docs/design/03-workflow.md:376` and `docs/milestones/M2.md:132` both write
`docs/evidence/{n}-{ts}.md`. `{n}` is defined nowhere as an issue number and

**6. `{ts}` has three formats, and the note recording that is itself wrong.**

`docs/design/01-skill-hierarchy.md:440` and `docs/design/06-domain-health.md:563`

**7. `## iai-verdict`'s first line is claimed by two rules at once.**
`docs/design/03-workflow.md:388` requires the sentinel to be the first line with

Both cannot govern the same line. The regex traces to

**8. 65,536 has no source in this repository.** It is asserted three times

## Vision

A caller holds a comment list and an artifact. It asks this layer three
questions — *is this sentinel well-formed*, *which comment carries it*, and
*does this payload fit* — and gets back a typed answer, a rendered body and an
instruction to create or to edit. The adapter does the reading and the writing.

The whole surface is total functions over plain data, so the test suite is a
fixture corpus and needs no issue, no token and no network.

## Out of Scope

- **Reading or writing anything.** No `fetch`, no `child_process`, no `Bun.$`,
  no filesystem. The comment list arrives as a value (Decision 1).
- **Constructing `gh` argv.** S1.3 owns it and already shipped the three
  functions this layer directs: `commentCreate`
  (`packages/core/src/gh/comments.ts:37`), `commentEdit`
  (`packages/core/src/gh/comments.ts:55`) and `commentList`
  (`packages/core/src/gh/comments.ts:74`). Decision 10 of
  `docs/design/stories/21.md:215` drew this boundary; this Story honours it from
  the other side.
- **Computing a commit SHA.** A permalink is *validated* and *assembled* here;
  the SHA is an input. Resolving `HEAD` is I/O.
- **Writing the artifact to disk.** This layer produces the path and the body.
  Committing them is the adapter's.
- **`DomainBinding` and the registry.** S1.5 (#31). This Story exports the
  constants that Story validates against (Decision 11).
- **Writing `references/evidence-artifacts.md`.** M2, and
  `docs/milestones/M1.md:276-279` says M2 cannot begin it until this Story
  merges.
- **Retrofitting the 22 existing artifacts.** They are immutable
  (`docs/design/stories/243.md:99-100`).

## Constraints

- **Purity, at the standard S1.2 and S1.3 hold.** No I/O, no `process.cwd()`,
  no Bun globals, no node builtin. Neither the `no-io-in-pure-modules` rule nor
  the stubbed-runtime harness covers this directory today (Decision 9).
- **Total functions.** No hostile input throws. A malformed sentinel, an
  unparseable timestamp and a branch-named permalink are all typed failures.
- **Fail closed.** Absence of a required sentinel is a hard-failure `Decision`
  and never a default (`docs/milestones/M1.md:170-171`). An unknown path
  placeholder is a construction failure, not an uninterpolated literal.
- **Evidence is immutable, and additions are expected.**
  `docs/design/stories/243.md:99-100` prohibits *modification*, not creation.
  The check that expresses this is `--diff-filter=MD` (Decision 12).
- **The sentinel namespace is closed.** Nine names,
  `docs/design/03-workflow.md:372-382`. A tenth is a Design change, not a
  runtime value.

## Goal

Every sentinel iAI writes is well-formed by construction, every sentinel it
reads is found deterministically or fails loudly, and no payload can silently
exceed what GitHub will accept.

### Decision 2 — the producer upserts, the consumer does not assume it

`CLAIM-26.2` and `CLAIM-26.6` are not in conflict once they are read as
describing **two different surfaces**.

`CLAIM-26.6` is a guarantee about *iAI's own writes*: given a comment list that
already carries the sentinel, the producer returns an edit instruction naming
that comment. That is a property of this layer, and it is testable here.

`CLAIM-26.2` is a requirement on the *consumer*, which reads a comment list this
layer did not create. Three `## iai-verdict` comments are reachable in at least
four ways the producer cannot prevent:

- **A human wrote one.** `docs/design/02-roles.md:431` requires a risk override
  to be "an explicit human comment on the Story under `## iai-risk`". A human
  is not bound by an upsert.
- **History predates the engine.** Every sentinel posted before S1.4 ships was
  posted by hand.
- **An edit failed.** The adapter can create, then fail to record the id.
- **Two producers ran against a stale list.** The list is a snapshot
  (Decision 1); two callers holding the same snapshot both decide "create".

So the producer never stacks, and the consumer never assumes it. The upsert is a
guarantee about writes, not an invariant of the comment list, and a consumer
that trusted it would be a consumer that breaks on the first human comment.
`docs/design/03-workflow.md:404-405` already legislates the consumer side —
"use the most recent by `createdAt`. Earlier ones are history, not state" — so
this reading is the one the workflow document already assumes.

**Ties are resolved deterministically, not arbitrarily.** `createdAt` has
one-second resolution on the GitHub API and the five artifacts sharing
`20260902T071821Z` on disk show batched writes are real. Equal timestamps
resolve by the highest comment id, because ids are monotonic per repository and
`packages/core/src/gh/comments.ts:51-54` already establishes that the id is the
addressable key. Without this rule `CLAIM-26.2` is satisfiable by a function
that returns either of two comments.

### Decision 3 — five rules, and the claim is restated rather than corrected later

`docs/design/03-workflow.md:388-392` is the specification. `CLAIM-26.1` is a
milestone *seed* — `docs/milestones/M1.md:164` calls the acceptance criteria
"these seed the Design claims", and `PLAN.md:200-203` makes the Design's Build
Targets table authoritative over the milestone. The seed dropped one row of a
five-row table.

The dropped rule is not decorative. It is the only one that rejects
`### iai-design` and `## IAI-Design`, and heading level is precisely what a
markdown author gets wrong. Shipping four rules would leave the fifth
unenforced and invisible — the `skill-lint` failure mode recorded at
`docs/design/stories/21.md:339-341`.

So the claim above says five. This follows S1.3's precedent exactly: Decision 2
of `docs/design/stories/21.md` restated `CLAIM-21.3` in the Design "to say this
rather than to be corrected later". The milestone line is not edited, because
it is pre-registered; the divergence is recorded here and in the evidence.

### Decision 4 — name-plus-boundary matching

`docs/design/03-workflow.md:400` uses `startswith("## iai-verdict")`. Taken as
the matching rule it has two consequences the tree never addresses.

The first is wanted: `## iai-verdict PASS` matches, and two worked examples use
that form (`docs/design/04-domain-dev.md:474`,
`docs/design/05-domain-trading.md:581`). Trailing payload on the sentinel line
stays legal.

The second is not: `## iai-design` would also match a comment opening
`## iai-designation`. No current name is a prefix of another — the nine at
`docs/design/03-workflow.md:372-382` are prefix-free — so this is a latent
hazard, not a live bug. It becomes live the moment a tenth name is added, and
the person adding it will not be reading this layer.

The rule is therefore: the first line matches `## iai-<name>` followed by end of
line or whitespace. Prefix-freedom of the namespace is asserted as a property of
the constant, not assumed.

**This also settles Problem 7.** `docs/milestones/M2.md:164-165`'s
`#{n}: (PASS|FAIL|TESTS_SKIPPED|PARTIAL)` regex governs the agent's stdout —
`docs/design/02-roles.md:614-616` states that in terms — and not the comment
body, whose first line is the sentinel. The verdict may still ride on the
sentinel line as `## iai-verdict PASS`, which is how both worked examples
already write it.

### Decision 5 — what the 5,536 characters are for

`docs/design/03-workflow.md:413` decides on **artifact size**.
`docs/milestones/M1.md:174` constrains the **emitted comment body**. These are
different quantities and both are enforceable, because the gap between 60,000
and 65,536 is exactly the room the envelope needs:

- The inline/summary choice reads the artifact length, as
  `docs/design/03-workflow.md:415-416` specifies. `≤ 60000` inlines, which
  settles the 60,000 boundary `CLAIM-26.4` left open and
  `docs/milestones/M1.md:189` demands a fixture for.
- The rendered body is asserted against 65,536 after rendering.
- The envelope — sentinel line, metadata, permalink — therefore has a budget of
  its own: **5,536 characters**, and it is checked. The worked example at
  `docs/design/03-workflow.md:418-426` is about 180 characters, so the headroom
  is roughly thirty times the only concrete envelope in the tree.

This is the first place the 60,000/65,536 pair is given a reason beyond
inheritance. `docs/design/03-workflow.md:411` says the remainder is "headroom
for the sentinel, metadata and permalinks" and no document computes it. Making
the envelope budget explicit turns a slogan into a bound a test can fail.

**On 65,536 itself (Problem 8):** it is enforced as an unverified inherited
constant and marked as such at its definition, in the manner of Decision 3 of
`docs/design/stories/21.md`. Nothing in this repository establishes it, and a
comment saying so is cheaper than a claim that pretends otherwise. It is
enforced rather than dropped because the failure mode of an over-long body is a
rejected API call, and failing closed at 65,536 costs nothing if the number is
merely conservative.

### Decision 6 — the summary envelope

`docs/milestones/M1.md:186` names "summary rendering" a deliverable and no
document specifies it. The one rendered example,
`docs/design/03-workflow.md:418-426`, is adopted as the shape, and its implicit
fields are pinned so they stop being implicit:

- the sentinel line, alone or with a trailing verdict token;
- a metadata line carrying Story, run timestamp and verdict;
- a counts line, where the producer has counts;
- a size statement naming the artifact's actual length;
- the SHA-pinned permalink, as a bare URL on its own line — the example uses a
  bare URL, not a markdown link, and a bare URL survives being pasted into a
  terminal.

`NEVER-26.10` makes the permalink non-optional, because a summary without one is
a dead end: the payload is on disk and nothing points at it.

**Truncation is not a strategy.** `scripts/bootstrap-github.sh:44` truncates
milestone descriptions at a 10,000-character budget, and it is the only
over-budget precedent in the tree. It is deliberately not adopted:
`docs/design/03-workflow.md:416` says summary *plus permalink*, and
`packages/core/src/gh/comments.ts:24-27` already records that the choice between
truncating and summarising is this Story's to make. A truncated artifact is a
silently incomplete record; a summary plus a permalink is a complete one.

### Decision 10 — nine sentinels, three artifact paths

`docs/design/03-workflow.md:372-382` lists nine sentinels. Four are inline-only,
one writes to `USER/TRADING/JOURNAL/{date}-*.md` and one to a KB PR. Only
`## iai-design`, `## iai-test-plan` and `## iai-evidence` have artifact paths
under `docs/`.

`CLAIM-26.1`, `CLAIM-26.2` and `CLAIM-26.3` — producer form, consumer
disambiguation, absence — apply to all nine. `CLAIM-26.4`, `CLAIM-26.5` and
`CLAIM-26.6` — budget, permalink, path template — only mean anything where an
artifact exists. No document draws that line, and `EvidenceSpec` has a single
`sentinel` field, so a binding cannot express it either.

The engine therefore models the namespace as a closed constant of nine, and
artifact-bearing behaviour is conditional on a path template being present
rather than on the sentinel's name. A binding that declares a path template for
an inline-only sentinel is a validation failure, which is a check S1.5 can make
because Decision 11 gives it the constant.

**One consequence is recorded rather than solved.** If the upsert is keyed on
`(issue, sentinel)`, two different gate kinds firing on one issue collide, since
`docs/design/03-workflow.md:379` gives `## iai-gate` a producer of "any gate
trigger" and `docs/design/03-workflow.md:270` allows one gate comment per issue.
That is M3's problem — `docs/milestones/M3.md` owns the gate lifecycle — and
this layer's key is stated explicitly so M3 finds a decision rather than an
assumption.

### Decision 12 — the immutability check, fixed where it can actually land

`docs/design/stories/243.md:123` and `docs/test-plans/243-plan.md:86` both
verify evidence immutability with
`git diff --name-only main...HEAD -- docs/evidence`. That command returns the
Story's **own added** artifacts, so it reads as a failure on every Story that
writes evidence — which is every Story. #243 hit it, #21 hit it again, and
`docs/evidence/21-20260902T100227Z.md:148` records the corrected form.

`docs/design/stories/243.md:99-100` prohibits *modification*: "No file under
`docs/evidence/` is modified". `--diff-filter=MD` expresses exactly that and
`--name-only` alone does not.

There is no test-plan template file to fix — `docs/test-plans/` holds five plans
and no template. So the correction lands the only way it can: **this Story's
plan is written with `--diff-filter=MD`, and this Decision is the citable
precedent** for the ones after it. The three existing plans are not edited;
they are pre-registered, and `docs/evidence/` is immutable.
