## The observation this module is built around

`subIssues` and `addSubIssue` require `-H "GraphQL-Features: sub_issues"`.
Without it the API returns **no nodes and no error**, which is
indistinguishable from an instance that has no sub-issue API at all.

Observed directly on 2026-09-01 against `dev-pmallapp/iAI` while decomposing
this Story: a `subIssues` query on #243 returned empty and read as though the
fallback path was in use, when all three of its tasks were real sub-issues.

That is a **false negative on the capability probe**, and it is the most
damaging failure this module could have. It does not error. It silently and
permanently selects the degraded path on a fully-capable instance, and every
issue tree built while it is wrong loses its real parenting.

The header is therefore attached by the constructors and is **not a caller
option**. `subIssueCapabilityProbe` is the probe command that
`docs/design/04-domain-dev.md:504` presupposes ("probed once per session and
cached") but which existed nowhere in the tree — that document specifies a
*result*, never a mechanism.

## The capability is reported, never discovered here

A probe is I/O and a cache is session state; this directory can hold neither.
Per Decision 1 of `docs/design/stories/21.md` the capability arrives as a value,
the same way S1.2 resolved consent. An unreported or invented capability value
is refused rather than defaulted, because defaulting it would be this layer
guessing at exactly the fact it cannot observe.

## Decision 5 — shapes pinned, and one form deliberately dropped

No document in the tree shows a single line of either fallback shape.
`scripts/bootstrap-stories.py:198-201` is the only working precedent and is
adopted:

- `Parent: #N` at column zero, on its own line, exactly once
- the parent checklist under an H2 that is **exactly** `## Tasks`
- **order preserved, never sorted** — `docs/milestones/M2.md:123-125` requires
  `Blocked by:` lines to match "the parent checklist order", so sorting here
  would silently break a claim two milestones away

**The script's degraded form is not adopted.** It falls back to
`Parent: the S1.1 Story` when the parent number is unknown. A body link whose
entire purpose is machine-readable parenting must not have a prose variant —
that is a link which silently stops being a link, and nothing downstream can
distinguish "no parent" from "parent written in English". An unknown parent is
a construction failure here.

## Two refusals worth recording

**Re-parenting is refused, not silently rewritten.** Adding the same link twice
is idempotent, which `docs/design/03-workflow.md:170-172` requires of every
skill. Adding a *different* parent to an already-parented body fails, because a
body carrying two `Parent:` lines is a corruption that would survive silently.

**The fallback refuses to emit a body link without the sibling list.**
`CLAIM-21.2` requires both halves: a link with no parent checklist leaves the
parent unable to enumerate its children, which is exactly what `status` reads in
fallback mode (`docs/design/04-domain-dev.md:504`). Emitting half the fallback
would produce a tree that looks parented from below and empty from above.
