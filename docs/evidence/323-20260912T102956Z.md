### Case 9 — the duplicate create, on the argv and not the exit code

`--inject` selects `INJECTION_ROSTER`: five frozen scenarios, one per
`FailureMode`. Run 1 POSTs a milestone; the lie drops the last element of the
one-element list; run 2 reads absence and POSTs the identical title. The fake
has no duplicate check on any identity key, so it lands:

```
run 1  gh api --method POST repos/OWNER/REPO/milestones -f title=M9 — universal lifecycle …
run 2  gh api --method POST repos/OWNER/REPO/milestones -f title=M9 — universal lifecycle …

harness: FAIL run-2-mutated: scenario "goal-create/injected-truncated-list"
         made 1 mutation(s) on run 2.
harness: verdict: fail (exit 1)
```

The assertion is on the **recorded argv**, never the exit code — #320's M9/M9b
pair measured that a double which refuses and a double which accepts return the
same verdict and differ only in **state**.

**The lie is armed between the runs, never before run 1.** All five are lies
about what run 2 *sees*. Arming one for run 1 leaves nothing genuine for run 2's
create to duplicate, and the harness would have proven nothing.

**A non-zero exit under `--inject` is the success condition of the mode.** The
wrapper still assigns `exitCode = verdict.exitCode` unconditionally. Inverting
it under `--inject` would move the branch-on-the-verdict one file over from
`decideVerdict`, which case 24 statically forbids; a branch does not stop being
a branch by relocating.

### Two findings from case 9, reported and not forced

- **Three of the five modes collapse to one signature.** The read-lie trio —
  zeroed budget, header-absent 403, transient connection error — all crash run 2
  identically on `JSON.parse` of empty stdout, because no transcription checks a
  read's exit code before parsing. This is **#320's finding reproduced one layer
  up**, and it belongs to **#331**. At the fake's own response level the three
  remain distinguishable, so the collapse is the transcriptions' handling, not
  the fake's modelling.
- **`silent-no-op-mutation` is armed but never engaged.** All four
  transcriptions are correctly idempotent under honest reads, so run 2 attempts
  no mutation for the lie to intercept. Verified at `createFakeForge`'s own seam
  instead. No bug was invented to force it.

### Cases 16 and 18 — the audit and the gap are the same fact

`docs/audits/293-transcription-audit.md` carries 16 rows, one per `## Re-entry`
row, each naming the transcription step, the mutation it gates, and the
reasoning. **It is not an evidence artifact**: `evidence-upsert.test.ts:33-50`
requires every file under `docs/evidence/` to match `{issue}-{ts}.md`, and an
artifact is immutable once pushed — the wrong lifetime for a record that must be
amended whenever a table or a transcription changes.

The audit's finding: the ordering obligation the bodies state is **per-row** —
*"every mutating step is preceded by the read that decides it"* — never
table-wide. **Three of the four transcriptions execute rows out of table order**,
each for a recorded reason, and all three are faithful. That is precisely why
case 16 passes when the harness fails to notice a reordered table: a harness
that went red on a reorder would assert an ordering the bodies never claimed,
and would go red on three of four skills as shipped.

Two authorised mutations are **dead in the roster** — `goal-create`'s milestone
`PATCH` and `story-create`'s `--milestone` reassign. Both are the fake's
unmodelled shapes, not transcription defects. The audit **records** them; only
the live rung (#324) can close them. This discharges the handoff's *"needs an
issue if #323's audit or #324's live rung does not absorb it"* as a record.
