## The defect, measured before and after

`reference-citation-count` shipped in #280 as a required check capping a skill
at **3** references. `CONTRIBUTING.md` independently mandates **3** for every
skill — `:272`, `:276`, `:280`. Three mandated against a cap of three admits
only a skill with **no dependencies of its own**.

Each Tier-1 verb was run through the real rule, using the `Reads` column of
`docs/design/01-skill-hierarchy.md:92-105`:

| skill | baseline | own | distinct | before | after |
|---|---|---|---|---|---|
| `goal-create` | 3 | 1 | 3 | ok | ok |
| `story-create` | 3 | 1 | 4 | **REJECTED** | ok |
| `story-design` | 3 | 1 | 4 | **REJECTED** | ok |
| `story-test-plan` | 3 | 0 | 3 | ok | ok |
| `task-create` | 3 | 1 | 4 | **REJECTED** | ok |
| `task-do` | 3 | 1 | 4 | **REJECTED** | ok |
| `task-verify` | 3 | 2 | 5 | **REJECTED** | ok |
| `story-verify` | 3 | 2 | 5 | **REJECTED** | ok |
| `size` | 3 | 1 | 4 | **REJECTED** | ok |

**Seven of nine rejected, including two of the four S2.2 must write.**

**Both survivors survived by accident.** `goal-create`'s own reference *is*
`context-discovery`, already in the baseline. `story-test-plan` reads
`binding.verify`, which is not a reference at all. Neither passed by design, and
that is the strongest evidence the cap was unsatisfiable rather than merely
tight.

**Splitting could not have helped.** The fourth citation is the universal
baseline, identical for every skill, so both halves of a split skill still need
four.

## The context budget was measured, and it was wrong

The design estimated references at *"~1–3k each"* and one Task at *"12–15k"*.
Those numbers predate any reference existing. Measured:

| Baseline reference | bytes | ~tokens |
|---|---|---|
| `context-discovery.md` | 5400 | 1350 |
| `gh-operations.md` | 6435 | 1608 |
| `gh-error-handling.md` | 6511 | 1627 |
| **total** | **18346** | **~4586** |

So one Task is `2k + 4k + 3k + 4.6k` baseline plus what it reads — **~17k, not
12–15k**. The blockquote is corrected in place rather than left to flatter.

**The `~2k` do-nothing invariant is preserved**, and that is why part C makes
the baseline *router-read-on-route* rather than *Tier-0 resident*. A session
that routes nothing still costs ~2k. A session that runs two verbs now pays the
baseline once instead of twice.

### M8 found a real weakness in this task's own test, and it was fixed

The first version of the CONTRIBUTING assertion checked that the word
`"baseline"` appeared **somewhere in the file**. M8 removed it from one of the
three checklist items and the test **stayed green**, because the other two still
carried it.

> A file-wide `toContain` cannot express a per-item property.

Rewritten to locate the item owning each baseline reference and assert *that
item* calls it baseline, with the item count asserted first so a failed split
cannot pass vacuously. M8, M9 and M10 then all kill. This is
`docs/evidence/33-20260904T113934Z.md`'s lesson — **assert the reason, not
merely that something somewhere was true** — recurring in a new place.

### M7 is a correct survivor, and it exposes one soft spot

Giving a verb a third own-reference does not fail, and should not: the cap is 5
and the headroom assertion is **relative** (`cap > measured max`), so it adapts
correctly. But the derivation comment says *"the measured maximum is TWO"* and
**nothing pins that 2**. If the design grows a verb to four own references, the
comment silently becomes false while every test still passes.

**Not acted on.** Pinning it would hard-code a number the design owns, which is
the defect `path-refs.test.ts:300` was rewritten to avoid. Recorded as the
honest cost of a relative assertion.
