## Findings — recorded, not acted on

**1. The plan's own case count is internally inconsistent.**
`docs/test-plans/21-plan.md:60` states *"21 cases — 17 P0 / 4 P1 / 0 P2"*. The
case tables at `:62-109` yield **18 P0 / 3 P1**, and the Coverage table at
`:47-58` agrees with the tables, not with the summary. Only cases 9, 12 and 16
carry P1. The verdict is unaffected — all 21 pass either way — but the summary
line is wrong and the plan is a pre-registered document, so it is **recorded
here rather than silently corrected**.

**2. Case 2's verifier as written is wrong, and was not implemented as written.**
The plan specifies *"`grep` over the directory"* for the three banned tokens.
#253 implemented it against the real rule instead — `FETCH_CALL_RE` is
`/\bfetch\s*\(/`, not a substring test. This was already known (handoff §3
finding 3) and is restated here because the story-level run confirms it: an
anchored grep for `child_process`, `Bun.$` and `fetch(` over the directory
returns **0**, so the plan's literal command happens to agree today — but only
because no prose in the directory currently contains the word *fetched*. It did
during #22, and the naive verifier failed on correct code then.

**3. The substring trap is live in the directory right now.** Case 21's literal
verifier is anchored (`pr merge`) and returns **0**. A naive `grep -rn "merge"`
over the same directory returns **10+** hits, every one legitimate:

| Hit | Why it is not a violation |
|---|---|
| `pr.ts:21,28` | Comments stating the subcommand is deliberately absent |
| `pr.ts:185-187,204-205` | `mergedAt` / `mergeCommit`, real `--json` fields |
| `pr.ts:191` | `INVALID_PR_VIEW_FIELDS` — rejects `merged`, which is not a field |

`NEVER-21.10` compares argv elements with `===`, so it is unaffected. Three
false positives on correct code were paid for during this Story; this is the
fourth instance of the same disease and it is worth the plan template saying so.

**4. Evidence immutability holds at story scope, and the story-scope command
matters.** `git diff --name-only --diff-filter=MD main...HEAD -- docs/evidence`
returns **0**. Without `--diff-filter=MD` the same command returns the five task
artifacts this Story legitimately added (#22, #23, #24, #25, #253). This Story's
plan has no evidence-immutability case, so nothing here depended on it — but it
independently confirms handoff §3 finding 1 at a second Story.
