### The six-scenario matrix, and why it is six rather than two

The plan asks for one comment-only scenario and one file-only scenario. Four
more were required to make the surfaces separable at all:

| Scenario | What the subject does | `attemptedMutations` | `writes` | HEAD | tree | dirty |
|---|---|---|---|---|---|---|
| **N** | one `gh` read, one `git status` | 0 | 0 | = | = | false |
| **F** | a read, then `gh issue comment` | **1** | 0 | = | = | false |
| **W** | a differing-bytes write, uncommitted | 0 | **1**, `identical: false` | = | = | **true** |
| **I** | a byte-identical rewrite | 0 | **1**, `identical: true` | = | = | false |
| **C** | a differing-bytes write, committed | 0 | **1** | **≠** | **≠** | false |
| **E** | a byte-identical rewrite, then `git commit --allow-empty` | 0 | **1**, `identical: true` | **≠** | = | false |

**N is the load-bearing one.** Without a scenario that mutates nothing, a
recorder that reported every run as mutating would pass all five others. It is
also where this task's non-vacuity comes from — there is no runner and no exit
code to lean on, and #322 owns both.

**E is why there are three worktree observables and not one.** `git commit
--allow-empty` after a byte-identical rewrite moves HEAD while leaving
`HEAD^{tree}` byte-identical. A recorder sampling only the tree hash cannot
distinguish a committed identical-bytes rewrite from an uncommitted one — and
neither of them appears on the forge surface at all, because `isMutatingGhArgv`
returns false for every `git` argv by construction.

**The zeros are asserted, not implied.** `F` asserts `writes` is empty and `W`
asserts `attemptedMutations` is empty. The non-zeros prove each surface is
wired; only the zeros prove the two are independent. One counter fed by both
inputs passes every non-zero assertion and reports "two surfaces" while having
one — mutation N2's shape, and the reason Decision 6 asks for a scenario that
trips **only** each surface.

### M5/M6 is the pair that carries the argument, and it is #320's M9/M9b one layer up

M5 weakens the matrix assertion from `toEqual` to a length check and **survives
alone**, because it injects no defect. M6 adds one: a recorder classifying on
`argv[1] === "issue"` instead of the shared `isMutatingGhArgv` — which admits

assertion the counts still line up for the scenarios whose totals happen to

classifier-agreement test, which asserts the recorded list equals a mixed

The lesson is the one #319's M3 and #320's M9 both recorded, arriving a third
time in a third shape: **a weakened assertion is not detectable by the test it
weakens.** Only an independently-shaped assertion over a deliberately mixed
population catches it.

## Four findings

### 1. The write seam is the only mechanism that can satisfy the third clause, and every alternative fails for one shared reason

The issue's verdict has three clauses, and the third — *no write to a tracked
path occurred* — is an **attempt** clause, while `git status --porcelain`,
`git hash-object`, a `--stat` diff and an mtime comparison all sample
**effect**. The entire distinguishing feature of an identical-bytes rewrite is
that it leaves no effect. An attempt cannot be recovered from a state sample
whose defining property is that the state did not move. The write seam is the
worktree's `createRecordingPort` — the same mechanism on the other surface,
which is what makes the two surfaces genuinely parallel rather than one real
surface and one heuristic bolted beside it.

### 2. The seam can be bypassed, the bypass is detected at run time, and the detector's blind spot is the same one the seam exists to cover

If `writes` is empty and the worktree moved, something wrote outside the seam,
and `mutationEvidence` says so in its own distinct phrase. That converts an
unfalsifiable worry into a measured event — M10 proves the clause is load-
bearing. **It cannot see an identical-bytes bypass**, because such a bypass
leaves HEAD, tree and dirty status all unchanged. That hole is stated in the
module, in the test, and here, so nobody later reads the detector as complete.

The static half is the sanctioned-writer list: three files today
(`fixture-repo.ts`, which seeds before the window opens; `tempdir.ts`; and the
recorder itself), asserted as a **list**, over a population that is a flat read
of `packages/harness/src`. M11 proves it names the offender. The population
grows automatically when #322 and #323 add modules, which is the point — a
fourth writer must be a deliberate edit to that list in front of a reviewer.

### 3. Tracked-ness is recorded and must never become a filter

A Design file is **untracked at the moment it is created** — that is what makes
it a creation. A recorder filtering writes on tracked-ness would score
`story-design` writing its Design as zero mutations, which is the argv-only
defect of Problem 6 reproduced inside its own fix. `trackedAtBegin` is sampled
once, at `begin()`, from `git ls-files`, because a file created during the run
and then `git add`-ed would read as tracked at `end()` and lie about the moment
of the write.

### 4. The observer had to be kept out of its own observation, and the assertion for it must be a list

The recorder's three probes (`rev-parse HEAD`, `rev-parse HEAD^{tree}`,
`status --porcelain`) run on the **raw** port; only the subject's calls go
through the recording wrapper. Had the probes gone through the wrapper,
`report.calls` would be non-empty for a subject that issued nothing, and case
11's *"a run 2 with zero mutations and zero reads did not run at all"* would be
permanently unfalsifiable. M9 kills the wrong wiring — but **only because the
assertion is the exact argv list**. A `calls.length > 0` check would pass with
the observer's own probes filling it in.
