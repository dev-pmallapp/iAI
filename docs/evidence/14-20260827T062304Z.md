### Why this is not a clean PASS

The case says rows carry **one of `confirmed`, `corrected` or `invented`**. 227
rows carry a fourth verdict, `original`. That is a deviation from the case as
written and from ISC-6's own wording, and it needs the principal, not me.

The reason is in §Verdicts of the document. ISC-6 defines `invented` as "searched
in all three sources, no corresponding statement exists" and requires a commit
removing or correcting every such row. Row 10 of section 1 confirms **LifeOS has
no trading** — zero broker integration, zero ticker resolution, zero quote code.
Under the literal reading, all 607 lines of `05-domain-trading.md` are `invented`
and ISC-6 demands a commit deleting each. The same argument deletes the
domain-binding seam, the rung ladders, the gate vocabulary, the risk officer —
227 rows, essentially every part of iAI that is a synthesis rather than a copy.

So `invented` is scoped to assertions that **make a source claim** and are wrong,
and net-new design making no source claim verdicts `original`. The teeth are
untouched: all 24 false-provenance rows were found, and all 24 were corrected.

This is the same shape as the strict-5 frontmatter question on #13, which was
adjudicated by the principal rather than settled by the implementer. **The gate
should ratify or reject the fourth verdict.** If rejected, the alternative is to
amend ISC-6's wording; deleting 227 rows of design is not a real option.

## Case 22 — skill-lint rejection correlating to a `corrected` row

**Criteria:** *The linter's exit code transitions from non-zero to 0 after the
fix, and the corresponding `docs/design/verification-pass.md` row reads
`corrected` and cites the fixing commit.*

**Result: TESTS_SKIPPED.** The precondition cannot be constructed.

`scripts/skill-lint.ts:394` collects a file only when its basename is exactly
`SKILL.md`. Nothing in `docs/design/` is a `SKILL.md`, so the linter has no
verdict to give about a docs target. Pointed at one directly:

```

skill-lint: metadata-nested           0 violations
skill-lint: 0 SKILL.md files scanned, 0 errors, 0 warnings

```

Zero files scanned, exit 0. The default target is no better — `skills/` contains
only `.gitkeep`:

```
$ bun run skill-lint
skill-lint: 0 SKILL.md files scanned, 0 errors, 0 warnings
$ echo $?
0
```

There is no input for which skill-lint's exit code transitions from non-zero to 0
on a docs target, so the case cannot execute in either direction.

This is not a gap opened by #14. It is **conflict row 19** of the register,
recorded during #13: `M1.md:62` scopes skill-lint to "the three docs targets",
while the ISA test strategy, `CONTRIBUTING.md:113`, `ci.yml:107` and the shipped
script all scope it to `skills/` only. #13 shipped the `skills/`-only reading
after the principal's strict-5 adjudication, because `references/` is "contracts,
not skills" (`08-dual-target.md:485`) and `agents/` must omit `name` on opencode
— one schema cannot span all three.

Case 22 was written against the `M1.md:62` reading. The shipped linter implements
the other one. Marking it PASS would require asserting an exit-code transition
that cannot be produced, so it is reported as unexecutable and left for the gate.

**Consequence for #13.** The handoff recorded case 22 as PARTIAL for #13, with
its second half to be upgraded by #14's output. The second half — "the
corresponding row reads `corrected` and cites the fixing commit" — is now
