## Why the harness cannot pass vacuously

A harness whose stubs silently fail to install proves nothing. This one arms the
traps, then **proves they are armed** by calling each directly and asserting it
throws, before exercising any module.

That step earned its keep during development. A Proxy-based mock reported
`typeof stub.readFileSync === "function"` while calls still reached the real
`fs`, because Bun copies property descriptors onto an already-resolved module
rather than delegating through a Proxy `get` trap. The arming assertion caught
it; a naive harness would have shipped green and worthless.

## Process isolation, and the CI failure that forced it

`mock.module()` patches Bun's module registry for the whole **process**, not the
calling file, and `mock.restore()` does not restore the real module. The throwing
`node:fs` leaked into sibling test files and broke
`packages/core/test/commit-prefix.test.ts`'s real-git integration case, which
calls `mkdtempSync`.

```
error: purity harness: node:fs.mkdtempSync must never be called from
       classify/ or guards/ (CLAIM-15.6)
(fail) checkCommitPrefix commit-msg hook integration (case 24)
```

**It was invisible locally and appeared only in CI**, because whether it bites
depends on the order Bun loads test files: locally this file ran last, in CI it
ran first. The green local run was luck, not evidence.

The harness now runs in a child process, its global mocks confined to a process
that loads nothing else. The parent does not merely assert exit 0 — a child that
collects no tests also exits 0, and Bun prints per-test names only on failure, so
a passing child would otherwise say nothing about which tests ran. The arming
step announces itself on stdout with a sentinel, and the parent asserts that
sentinel, a non-zero pass count, and the absence of any failure line.

## Mutation testing — the two mechanisms catch different things

Run twice: once before the restructure, and again after, because process
isolation could have left the harness able to catch a violation but unable to
report it.

| Mutation | Lint | Harness |
|---|---|---|
| `fs` imported, called from an **unreached** function | caught | **not** caught |
| `fs` called on `checkSpend`'s **executed** path | caught | caught |

Lint is structural and catches a dormant import before anything wires it up. The
harness is behavioural and catches I/O on paths actually exercised. **Neither
subsumes the other**, which is the concrete argument for shipping both, and why
CLAIM-15.6 resting on the harness alone would have had a real hole.

Both mutations were reverted and the file confirmed byte-identical.

## The lint rule

`no-io-in-pure-modules`, scoped to `packages/core/src/classify` and
`packages/core/src/guards`. Detects imports and requires of 20 runtime module
specifiers (bare and `node:`-prefixed), plus `process.` and `Bun.` member access
and `fetch(`. Runs against `maskComments()`-masked source, so the comment at
`packages/core/src/classify/path.ts:2` — which names `fs` and the cwd call in
prose — is correctly not flagged.
