### M1/M1b is the whole argument for cardinality, in one pair

With two scenarios seeded identically, a `hashes.length === roster.length`
assertion reports **12 pass / 0 fail**. The defect is *invisible*. The
`new Set(hashes).size` assertion reports `Expected: 3, Received: 2`.

> **A length check counts what you collected. A cardinality check counts what
> is distinct.** Two scenarios silently sharing a seed would have the harness
> report an idempotency result about the wrong repository, and every downstream
> denominator would still look right.

### 2. A no-op mutation is indistinguishable from a survivor

Between M3 and M3b I ran `git checkout -- <file>`, reverting an unstaged edit I
still needed. M3b's pattern then silently did not match, and the run reported
**12 pass / 0 fail** — which reads exactly like a survivor.

`.opencode/HANDOFF.md` warns about `git checkout --` destroying unstaged work,
and it still happened.

> **A mutation script must assert its pattern matched.** A no-op mutation
> reports the result you were hoping for. This is finding 37's shape — a
> harness misreading its own output as a verdict — at the level of the mutation
> rather than the runner.
