## Finding 37 (new). The mutation harness read its own fixture's prose as a verdict

The first M7 run reported **SURVIVED**. It had not survived — it killed two
tests.

The harness decided the verdict with `"0 fail" not in stdout`. The corpus under
test is a directory of **test plans**, and case 18 of `docs/test-plans/35-plan.md`
contains the literal prose *"63 pass, 0 fail"*. A failing assertion dumps the
whole document into the diff, so the string `0 fail` appeared in stdout — from
the **fixture**, not from the **runner** — and the harness read it as success.

> **A harness that decides a verdict by grepping stdout for a phrase its own
> corpus can contain is not measuring the run.**

Re-run with the exit code as the signal: `exit 1`, KILLED, two named failures.
This is a fresh instance of the class the repository already knows — format is
not existence, a condition that cannot hold is an assertion that does not exist —
and it is the first time it has bitten the **measuring apparatus** rather than
the thing measured. Owner: any future mutation harness. `docs/evidence/` is full
of `N pass, 0 fail` strings, so every artifact in this directory is now a live
trap for the same bug.

## What this check does NOT do, stated rather than implied

It verifies that every case **declares** a corpus and that the declaration is
well formed. It cannot verify that a declaration is **true** — a case whose
fixtures are invented can still be labelled `real`.

That is not a gap to be closed with a stricter regex. Judging fixture realism
from a prose cell is not a thing a linter can do, and a rule that pretended
otherwise would be the "stronger-sounding class than the check supports" failure
that `references/verification.md` already names. The declaration being required,
visible and machine-read is what stops it being forgotten, and being forgotten
is the failure #289 actually measured.

Written into the doctrine and into the Reconciliation table of
`references/verification.md`, so the bound ships with the rule instead of being
discovered later.

## The rule's own fixtures are the real roster, by construction

The defect being fixed is *tests that agree with a rule while telling you nothing
about the world*. Authoring invented plan text for this rule's tests would
reproduce that defect inside the fix for it.

So every negative fixture in `packages/core/test/testplan-corpus.test.ts` is the
**real roster with exactly one cell perturbed** — `perturbFirstCorpusCell` and
`dropCorpusHeading` both read a shipped plan off disk and change one thing. Two
positive cases are the unmodified roster. The "only case tables are counted" case
is proved against the real `35-plan.md`, which carries a Coverage table and a
Standing-checks table, rather than against a document built to agree with the
predicate.

The four messages are pairwise disjoint by phrase and every negative test asserts
the **absence** of the other three — the `docs/evidence/33-*.md` remedy, because
two messages that differ only in the value they quote are one message.
