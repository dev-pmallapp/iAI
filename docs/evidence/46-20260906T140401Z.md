## What shipped

`domain-routing-form`, a fourth body rule in `scripts/skill-lint.ts`. A body may
not carry a **routing form** — `domain:<id>` or `skills/<id>` for any id in
`KNOWN_DOMAIN_IDS`.

**The id list is imported, never restated.**
`packages/core/src/binding/domain.ts:68-72` declares itself the only place the
domain literals may appear, and `DomainId` is deliberately **open**. A rule
hardcoding five tokens would need editing to admit a sixth domain — the precise
failure `ARCHITECTURE.md:209` names — and would be a `duplicate-contract`
violation in its own right. Mutation M6 replaces the import with a literal list
and is killed.

### The carve-out is derived, not listed

`CONTRIBUTING.md:303-304` is exact:

> *"A leaf skill may know its own domain; a Tier-1 verb may never know any."*

So a body's **own domain** is read from its own directory: `skills/trade-backtest/`
owns `trade` and may name it; `skills/story-design/` owns nothing and may name
none.

This needs **no enumeration of the fourteen Tier-1 verbs**, so there is no list
to go stale as S2.3 through S2.5 add verbs. The rule derives Tier-1-ness from the
fact that a verb's directory name is not a domain id.

## Why the seeded rule could not ship

Measured over the twelve shipped references:

| Token | Substring | Whole-word | False positives under a substring ban |
|---|---|---|---|
| `know` | **16** | 3 | **13** — `known` ×7, `knows` ×2, `knowledge` ×2, `unknown` ×2 |
| `dev` | 5 | 3 | 2 — `deviation` ×2 |
| `health` / `trade` / `wealth` | 4 / 2 / 1 | same | 0 |

`know` is an ordinary English word and a whole-word rule does not save it. The
seeded carve-out — "outside a `references/` citation path" — **exempts 0 of 28
occurrences**, because none of the twelve reference filenames contains any of the
five tokens.

And it was self-contradictory: `references/domain-binding.md:13` — *"The kernel
does not know what `trade` or `health` means"* — holds four of the five banned
tokens and is the doctrine `CLAIM-41.5` requires these four skills to implement.

### M7 is the finding, and it is the third occurrence of one class

`ownDomainOf` grants the carve-out. Written as a bare prefix test —
`dir.startsWith(id)` — it hands `dev` to `skills/development-tools/` and `know`
to `skills/knowledge-base/`, **silently exempting a verb that is not a domain
pack at all**. My original tests covered `trade-backtest`, `dev`, `goal-create`
and `story-test-plan`; not one of them begins with a domain id without the
hyphen, so none could distinguish the two implementations.

> **An exemption expressed as a prefix admits anything that starts with it.**

Third shape of one defect, and the repository had already recorded the other two:

| Where | Shape |
|---|---|
| `docs/evidence/34-20260905T031229Z.md` | *"an exemption expressed as a line RANGE admits anything that fits inside the range"* |
| `docs/test-plans/35-plan.md` case 7 | a **prefix** match on the model-ID exemption *"would additionally exempt a hypothetical `model-routing-notes.md`"* |
| **here** | a **prefix** match on the own-domain carve-out exempts any directory beginning with a domain id |

Case 7 predicted this exact failure mode one Story earlier, about a different
exemption, and it still shipped. **Knowing the class is not the same as checking
for it** — which is the argument for running mutations rather than reasoning
about coverage.

**The direction matters.** An over-broad exemption is the dangerous one: a rule
that fires too often is noisy and gets fixed; a carve-out that is too generous is
silent and never does.

Fixed by making the carve-out **shape-based** — exactly the id, or the id
followed by a hyphen — with a regression test naming four directories that must
*not* receive it, plus an assertion that the two legal shapes still work, so the
leak was not closed by breaking the carve-out.

## A bug I introduced, and how it presented

Appending the new suite defined a second top-level `function realReferences()`
in `test/skill-lint.test.ts`, where #287 had already defined one returning a
different type. The later declaration silently won.

**All eight resulting failures were in #287's tests. None were in mine.** The
diagnosis pointed away from the culprit, and the only reason it was cheap to find
is that #287's tests are real-roster tests with specific assertions — a weaker
suite would have failed with a vague message or not at all.

> **A duplicate top-level `function` declaration does not error; it overrides,
> and the damage surfaces in the code that used the original.**

Renamed to `realReferenceDocs()`. Recorded because the failure mode — a green
file becoming red for reasons unrelated to the change — costs the most time when
nobody expects it.

## `NEVER-41.7` is NOT discharged, and that is asserted

`NEVER-41.7` requires the property proved *"over the real four-skill corpus, not
a fixture"*. **The four skills do not exist yet** — they are #42 through #45. The
skill population is **0** today; the contract population is **12**.

This rule therefore ships **before its own skill corpus**, which is the opposite
of how #280 was sequenced, and finding 36 of `docs/evidence/40-20260906T081054Z.md`
is explicit that sequencing a rule *after* its corpus is what stopped it shipping
wrong and green.

**The trade is deliberate.** A rule constraining how the four verbs are *written*
is worth more before they are written than after — the same preventive-beats-
detective argument #289 settled. What protects it is that the emptiness is
**asserted**, not assumed:

- a test asserts the skill population is **exactly 0** today, and says in terms
  that when it goes red the verbs have landed and `NEVER-41.7` becomes provable;
- a second test asserts the contract population is **>= 12**, so the rule is not
  vacuous in the meantime.

Nobody can mistake a green run for a discharged anti-claim.
