## What shipped

**`withTasksChecklist(body, items)`** — build target 1, modelled on
`withParentLine` one file over: it inserts into an existing body, it is
idempotent, and it **refuses the ambiguous case rather than guessing at it**.

| Behaviour | Why |
|---|---|
| Rewrites only the **leading run of entry lines**, never the whole section | Real Story bodies put load-bearing prose inside `## Tasks` — see below |
| Refuses a body with **two `## Tasks` sections**, naming the count | Two checklists are two answers to *"what are this Story's tasks"* |
| Refuses entries **split by prose**, naming the line | The structure is asserted, not assumed — #323's lesson |
| **Inherits a tick** the caller is silent about; an explicit `checked` wins | A tick is body content too |
| Rebuilds items field by field through `safeOwnValue`, **never a spread** | A spread runs a hostile getter; this module's corpus requires 0 throws |

**`parentBody` is required on both paths and has no default** — build target 2's
other half. A default of `""` would make the destructive behaviour the fallback
for a caller who simply forgot, which is the defect with a nicer signature. A
genuinely empty Story body is stated as `""`.

**The checklist edit is now emitted on the GraphQL path too.** At `a6ce084`
`planSubIssueAttach` returned exactly one command when the capability was
`"present"`, so `CLAIM-47.1`'s clause *"adds a `## Tasks` checklist to the
Story"* was **unreachable on the primary path**. Both paths now build the edit
through one helper, so they cannot drift into disagreeing about what *"adds a
checklist"* means.

## The finding that mattered, and it came from the one survivor

**M11 — widening the section boundary from `^#{1,2} ` to `^#{1,3} ` — survived
the first pass, changing not one assertion.** Chasing it down is what found the
real defect:

> **Every real Story body carries load-bearing prose INSIDE the `## Tasks`
> section, after the entries.** #47 carries its dependency ordering and the
> *"the git/argv layer in #49 is shared with #293's adapter port … it must not
> be built twice"* ruling there. #293 carries its sequencing rulings there —
> **and on #293 that section runs to the end of the body**, so there is no
> following heading to stop a section-wide rewrite.

The merger as first written replaced the section from its heading to the next
H1/H2. **Against #293 it would have deleted every one of those rulings.** The
fix for a body-destroying defect had reproduced the defect one level down,
inside itself, and the full suite was green across it.

The rewrite now covers the leading entry run and nothing else, and everything
from the end of that run onward is carried verbatim. `M13` re-injects the
section-wide rewrite and is killed by the real-shape fixture.

> **A green suite over the corpus you thought of is not evidence about the
> corpus that exists.** The fixtures were all "a body with prose *around* the
> checklist". Not one had prose *inside* it, which is what every real Story has.
> The survivor was the only thing pointing at the gap.

## The recovery verb destroyed the work it was recovering

Mid-round the mutation script's revert — `git checkout -- <path>` — ran against
a **dirty tree** and reverted the section fix, which was written but not yet
committed. `.opencode/HANDOFF.md` carries this trap in terms; it was read, and
hit anyway, at the one moment the round looked routine.

Two things made it a footnote rather than a loss:

1. **The script asserts the file is byte-identical to the committed state after
   each revert**, and that assertion fired on mutation 1 — not at the end of a
   13-mutation round with eleven results already written down.
2. The script now **refuses to start** while the files it reverts have
   uncommitted changes, which is the check that should have existed first.

> **A revert is a mutating operation.** It was treated as cleanup, and cleanup
> is the category of thing nobody guards. This is finding 40's shape at a fourth
> site: a recorded lesson does not check the next thing you write.
