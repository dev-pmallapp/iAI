## The scope decision, and why it is not an exemption

`no-domain-pack-import` is scoped to **`packages/core/src`**, not
`packages/core`. #34 gave `packages/core` a dev-only dependency on
`iai-domain-null` so the conformance suite could import the fixture *by package
name*; `packages/core/test/binding-conformance.test.ts` therefore imports a
domain pack deliberately.

`docs/design/stories/31.md:229-230` words the claim as "No file under
`packages/core/src`", so the predicate matches the claim exactly rather than
being widened to the package and then punctured. **An exemption is a hole; a
correctly drawn scope is not.** Mutation B3 makes the difference load-bearing:
scoping to the package alone fails case 21's `core/test` test *and* takes
`bun run lint` to exit 1 on the real tree.

## A real defect found and fixed: `domainLabelFor` was not total

`NEVER-31.8` is not a formality here. The reflective sweep found that **two of
the barrel's seven exported functions threw**, both on the same line:

```
domainLabelFor(Symbol())  -> TypeError: Cannot convert a symbol to a string
domainLabelFor({object})  -> Error: hostile toString
```

`` return `domain:${id}` `` is template interpolation, which is one of the few
operations that *throws on a value* rather than merely misbehaving. Every other
function in the layer routes reads through `own()` and was already total; this
one did not read a property, so it was never suspected.

The guard is unreachable from well-typed code — `id` is declared `string` — and
is kept for the three paths Decision 4 names: a pack authored in JavaScript, a
value that crossed a `JSON.parse` or a markdown parser, and an `as` cast.
Mutation C1 reverts it and the sweep goes red naming both inputs.

> A layer is total when its *messages* are total, not only its logic. The
> functions that build strings are the ones that throw.

## Two time caps, because a hang is not a throw

Case 18 is the first corpus in this repository to carry one, and it needed two.

**A synchronous hang cannot be caught in-process.** Not by `try`/`catch`, not by
`expect(fn).not.toThrow()`, not by `Promise.race`, and not by Bun's per-test
timeout — a synchronous loop never yields the thread, so nothing scheduled on it
ever runs. #261's mutation 7 produced exactly this: ~4×10^10 comparisons,
killed at 60 s.

So the sweep runs in a **child process with a wall-clock kill**
(`Bun.spawnSync({ timeout })`, verified against Bun 1.4.0 to terminate
`while(true){}` with `SIGTERM`), and a **per-call cap of 250 ms** catches the
slow-but-terminating case a wall clock cannot attribute to a function.

Both were proven by mutation:

- **C2** — `while (Date.now() > 0) {}` in `registeredDomainIds`: the parent
  failed at 30,050 ms with `Received: "SIGTERM"`, i.e. the cap fired rather than
  the loop ending.
- **C3** — a pathologically slow but finite path: the per-call cap fired,
  naming `registeredDomainIds("<200000 chars>") took 562.2ms`.

One implementation note worth recording: a healthy child reports
`signalCode === undefined`, a killed one `"SIGTERM"`. Asserting `toBeNull()`
alone **fails on a healthy run** — normalising with `?? null` is what makes the
assertion mean what it says. Caught on the first run.

### A6b is why three cases are not two

The obfuscated read leaves `bun run lint` at **exit 0 with 0 violations across
91 files** — the rule scans for `\bprocess\s*\.` and there is no such token —
while case 16 fails with a stack trace naming the exact line. This independently
reproduces #261's finding at a second directory. **A static rule certifies only
the source it can read.**

### The survivor, and the fix

Mutation A6 placed the same obfuscated read at **module top level** and survived
*both* defences. The cause is ordering, not detection: ESM evaluates static
imports before any test body runs, so `packages/core/src/binding/index` was
fully loaded **before `beforeAll` armed the traps**. I/O performed at module
evaluation time therefore ran against the real runtime.

Closed by importing the barrel with `await import()` **inside** the case-16
test, having removed the static import — a cached module is not re-evaluated, so
removing the static import is what makes the dynamic one meaningful. Re-running
A6 now fails with the trap's own stack trace pointing at `registry.ts:40`, while
lint remains blind. Confirmed, then reverted.

> An import is not "code that runs later". A static import runs **before** every
> guard your test file installs.
