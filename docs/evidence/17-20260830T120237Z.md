## Mutation testing — why cases 30 and 31 are not vacuous

A test asserting that a program **fails to compile** can pass for the wrong
reason, or for no reason at all. A passing run proves nothing on its own. Each
invalid fixture is therefore compiled twice: once with the `@ts-expect-error`
stripped, asserting the specific diagnostic, and once intact, asserting a clean
compile — which proves the directive matches that error and not another.

That design was then verified by breaking the type on purpose:

| Mutation applied to `packages/core/src/decision.ts` | Expected | Observed |
|---|---|---|
| `EgressDecision` widened to admit `warn` | case 30 fails | **case 30 failed** |
| `block` arm given `redacted?: unknown` | case 31 fails | **case 31 failed** |

Both mutations reverted; `decision.ts` byte-identical to the commit; suite
returned to 253 pass / 0 fail.

## The CI failure, and how it was found

Local runs were green while CI was red. `iai-core`'s exports map named only
`./dist/index.js`, and CI's `test` job runs `bun install` then `bun test` with
no build between them.

Nothing had hit this before: every pre-existing test imports relatively from
`../src`, and both adapter sources use `import type`, which is erased before it
needs resolving. This task's adapter tests are the repo's first runtime
cross-package import. The local pass was an artifact of a stale `dist/`.

Reproduced by deleting `dist/`:

```
error: Cannot find package 'iai-core' from packages/adapter-claude/test/index.test.ts
error: Cannot find package 'iai-core' from packages/adapter-opencode/test/index.test.ts
 237 pass, 2 fail
```

Fixed in `8f520ab` by adding a `bun` export condition pointing at source.
`main`, `types` and `default` are untouched. Re-verified from a fully clean
tree with no `dist` and no `tsbuildinfo`.
