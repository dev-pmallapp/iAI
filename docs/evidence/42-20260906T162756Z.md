## The exemption is named, counted and asserted

An exemption was unavoidable. **The dangerous way to write one was available and
was rejected**: a derived predicate such as *"bodies that do not cite
`references/domain-binding.md`"* would have silently exempted any future skill
that stopped citing it.

**An over-broad exemption is the silent direction**, recorded five times here
(`docs/evidence/34-*.md` line range, `docs/test-plans/35-plan.md` case 7 prefix,
`docs/evidence/46-*.md` prefix, #295's mutation M8, #44's rejected bare-word
matcher). So:

- the list is **literal** — `["goal-create"]`;
- its **length is asserted** (mutation G3);
- **every member must exist on disk**, so a stale exemption for a renamed or
  changed skill cannot sit unnoticed;
- the exempt body must **state in its own text** that it reads no domain, rather
  than relying on the test's list to explain it (mutation G1).

## What generalises, and what does not

The doctrine is **not** "read a `domain:` label". It is **"absence is a hard
failure, not a default"** — the phrase `packages/core/src/binding/registry.ts:115-122`
and `packages/core/src/evidence/consumer.ts:201-205` both use.

Asserted over **every** body, exempt or not:

| Property | Applies to |
|---|---|
| carries the house hard-failure block | all |
| the block names what it **Expected** | all |
| the block records **Found: none** | all |
| states the refusal explicitly (*not a default*) | all |
| carries no routing form for any domain id | all |
| reads the `domain:` label **before** the binding step | all **except** the named exemption |

Case 12's matcher moved off the literal token `domain:` onto that **shape**,
because the required input differs per verb — `goal-create` hard-fails on an
unresolvable goal, `story-design` on a missing label — while the doctrine does
not.
