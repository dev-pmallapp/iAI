## The equality boundary

Falls to **allow**. `docs/design/03-workflow.md:244` triggers the gate on an
outflow *above* the configured limit, so an amount equal to the threshold is not
above it.

```
amount=  99 threshold= 100 -> allow
amount= 100 threshold= 100 -> allow      <- the boundary
amount= 101 threshold= 100 -> block
amount=   0 threshold=   0 -> allow
amount=  -1 threshold= 100 -> block      <- incoherent input fails closed
amount= 100 threshold=  -1 -> block
```

## A defect found by probing, not by the tests

`checkRiskMandate` initially accepted only the bare rung name. Labels are the
source of truth for a Story's rung (`docs/design/03-workflow.md:96-98`, ladder at
`:135`) and carry the `rung:` prefix literally, so a caller reading one off an
issue holds `rung:research`.

```
BEFORE  checkRiskMandate(902, "rung:research") -> block
        message: "- Found: rung:rung:research"
```

Fail-closed, so never dangerous — but it would have refused **every legitimate
auto run**, and announced itself only as a doubled prefix.

**Not one of the 39 tests passed the label form.** One test actively encoded the
defect by listing `rung:paper` among the unrecognised rungs; it failed once the
defect was fixed, which is the correct outcome, and that entry was removed with
the reasoning recorded beside the list.

After the fix, both spellings agree and normalisation strips at most one prefix:

```
research        -> allow      rung:research   -> allow
paper           -> allow      rung:paper      -> allow
live            -> block      rung:live       -> block
rung:rung:live  -> block      rung:backtest   -> block
sandbox         -> block      "" / null       -> block
```

The generalisable lesson, recorded for #20 and M2: a guard whose tests only ever
feed it values in the shape the implementation chose will pass while being wrong
at every real call site.
