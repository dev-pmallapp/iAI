### Mutation 5 was a real gap, found and fixed before commit

Loosening the anchored SHA check from `{7,40}` to `{1,40}` broke **no test** on
the first run. A 6-character SHA was still rejected, because `makePermalink`
validates its assembled output against the blob-segment predicate as a backstop.
But the reason degraded from

```
permalink sha "47004e" is not a commit SHA; it must be lowercase hex, 7 to 40 characters.
```

to

```
assembled permalink failed its own validation: "https://github.com/a/b/blob/47004e/c.md"
```

**Correct rejection, useless message.** This is the same defect class as #27's
case 3, where five identical linter messages satisfied a test that only counted
rejections. Case 13 now asserts the message names the SHA rule and does not read
`failed its own validation`, and mutation 5 fails.

### Mutation 7 is a genuine equivalent mutant, and the guard is kept

Deleting `if (body.length > HARD_LIMIT_CHARS)` breaks nothing, and that is
correct rather than a gap. The branch is unreachable while the constants
compose: an inline body is at most `BUDGET_CHARS + ENVELOPE_BUDGET_CHARS` and
the envelope check has already returned; a summary body is envelope only. Since
`ENVELOPE_BUDGET_CHARS` is **derived** as `HARD_LIMIT_CHARS - BUDGET_CHARS`, the
sum is exactly 65,536.

It is kept because `docs/milestones/M1.md:174` states the 65,536 constraint
directly, and code that no longer mentions the number a claim names has quietly
stopped implementing it. **Mutation 8 verifies that the relationship making it
unreachable is itself protected** — hardcoding `ENVELOPE_BUDGET_CHARS = 10000`
fails case 11's compose assertion. A comment at the branch records all of this
so it is not deleted as dead code.

**Three kinds of surviving mutant, now all observed in this Story:** a missing
assertion (#27 case 3, #29 M5) fixes the test; a fixture that cannot distinguish
two keys (#28 M3) fixes the fixture; a genuinely equivalent mutant (#29 M7) is
documented and the code kept.

## Decision 5, and what the 5,536 characters are actually for

The three quantities are implemented as three separate checks because the
documents measure three different things:

| Quantity | Bound | Source |
|---|---|---|
| artifact size | inline vs summary at `<= 60000` | `docs/design/03-workflow.md:415-416` |
| rendered comment body | 65,536 | `docs/milestones/M1.md:174` |
| envelope (rendered minus inlined artifact) | 5,536 | Decision 5 — **appears in no document** |

`docs/design/03-workflow.md:411` calls the remainder "headroom for the sentinel,
metadata and permalinks" and nothing in the tree computes it. Making it an
enforced bound turns the slogan into something a test can fail, and it is what
makes the hard limit hold by construction. Case 9 settles the exactly-60,000
boundary that `CLAIM-26.4` never defined and `docs/milestones/M1.md:189` demands
a fixture for.

**65,536 is enforced as an explicitly unverified inherited constant**, marked as
such at its definition. Nothing here establishes it; every verification row
attributes it to forge's `gh-api.md`, a document in an ancestor repository.
