## Design conflicts found and deliberately not resolved here

Four, all routed to #14 under ISC-6:

1. **The key set is documented twice.** `08-dual-target.md:44-50` gives five;
   `01-skill-hierarchy.md:347-356` gives eight. The ISA resolves the schema by
   reference — "any frontmatter key outside the documented set" — pointing at
   the thing documented twice. Adjudicated to five by the human principal.
2. **`01-skill-hierarchy.md` contradicts itself.** Line 70 puts
   `disable-model-invocation` at top level for the Tier-0 `iai` router and line
   72 calls it "load-bearing"; line 366 says to put anything host-specific
   under `metadata`. Under strict-5 the router as specified cannot be authored.
   This will surface in M2.
3. **Skill layout is specified twice.** `01-skill-hierarchy.md:370` shows
   `skills/trade/backtest/SKILL.md` with `name: trade-backtest` — which fails
   its own name-equals-directory rule. `CONTRIBUTING.md:284` implies the flat
   `skills/<id>-*/` form, which passes. The linter implements the literal rule,
   so only the flat layout is valid.
4. **Scope is specified twice.** `M1.md:62` says "the three docs targets"; the
   ISA test strategy, `CONTRIBUTING.md:113`, `ci.yml:107` and the placeholder
   all pass `skills/` only. Implemented as `skills/` only —
   `08-dual-target.md:485` calls `references/` "contracts, not skills", and
   `agents/` files must *omit* `name` on opencode, so one schema cannot span
   all three.
