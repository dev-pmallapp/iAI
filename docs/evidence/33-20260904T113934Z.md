## The three survivors were all the same defect, and it is #261's

**Mutation 9 — a guard shadowed by another guard.** Deleting the `id` shape
check broke nothing. The only malformed-id fixture in the file was
`{ id: "Not A Domain" }` built from a helper that supplies
`labels.namespace: "domain:null"` — so the **namespace-agreement** rule rejected
it, and the shape rule was never the reason. The new case builds the namespace
to *agree* with the bad id, leaving the rule under test as the only one that can
fire, and sweeps six malformed forms.

**Mutation 15 — the same shadowing, one layer up, and worse.** Case 19's five
fixtures were each `validBinding()` plus a mutated `validBinding()`. Both carry
`id: "null"`, so the **duplicate-id** rule rejected every pair before the defect
under test was reached. **The case that proves "a rejected binding is never
resolvable" was passing five times for a reason unrelated to all five defects it
names.** Every fixture now carries a distinct id, and the case asserts the
*reason* rather than only the verdict.

**Mutation 4 — a redundant rule, and a distinctness assertion that was not
distinct.** Deleting `isSentinelNamespace` broke nothing, because every
out-of-namespace fixture is also caught by the known-name rule that follows it:
a value outside the namespace can never match a known name either. The rule is
redundant *against the corpus* while still being the only one that says the
right thing to whoever tripped it.

The first fix did not work, and that is the more useful half. It asserted the
two messages differ and that each contains `"namespace"` — but with the check
deleted, both fixtures fall through to the known-name rule, whose message *also*
contains the word "namespace" and *quotes the offending sentinel*. Two different
sentinels produced two different strings, so "the messages differ" held and the
mutation still survived.

> **Two messages that differ only in the value they quote are one message.**

The assertion now names a phrase belonging to exactly one rule and asserts the
*absence* of the other's phrase. That pair is what makes it exclusive.

**This is the second consecutive Story in which mutation testing found a guard
shadowed by another guard** — #261 named the class, and it has now appeared
three more times in one task. The lesson generalises: when several rules reject
the same fixture, the test proves only that *something* rejected it. Asserting
the reason is what turns a verdict into evidence.

## Decision 2 is structural, not asserted afterwards

`createRegistry(bindings)` is a pure function from a list to a lookup. There is
no `register()`, no module-level `Map`, no side effect. `NEVER-31.9`'s guarantee
follows from the shape rather than from a check: **if any candidate fails, no
`Registry` is produced at all**, so there is no object on which a rejected
binding could be resolved. There is deliberately no partial-success arm and no
"registered with warnings" — mutation 11 turns the early return into `continue`
and case 19 fails.

(`docs/milestones/M8.md:85-87`) needs for Pulse's per-domain rendering, sorted
so a dashboard does not reorder itself when the composition root changes its
list order.
