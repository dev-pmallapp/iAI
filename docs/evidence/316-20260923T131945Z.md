## The ruling that made the task shippable at all

**Build target 4's claim-to-artifact resolver cannot be built as the Design
specifies**, and case 8 depends on it. Measured over the 54 artifacts:

- **21 carry no `| Claims |` row at all**
- the other **33** use at least **five mutually incompatible notations** —
  `…`, `–` with an abbreviated endpoint, `..`, spaced `–`, and partial-coverage
  qualifiers — plus the retired `ISC-*` namespace
- **#287 has two artifacts**, so the mapping is not 1:1
- **`docs/evidence/` is immutable** (NEVER-194.6), so **the gaps can never be
  backfilled and the notations can never be normalised**

Which leaves exactly one sound direction:

> **SOUND** — a claim id appearing in **zero** artifacts is certainly uncovered.
> **UNSOUND** — a claim id appearing somewhere is therefore covered.

**`CLAIM-47.6` refuses, and a refusal needs only the sound direction.** So the
refusal ships as a pure function over a **supplied** resolution and **exports no
resolver**. Raised as **#341**; case 8 recorded **partially discharged** under
**G-b**.

**The carry:** build target 4 owns the positive direction, and #341 owns the
ruling on whether it is reconstructed from the Design/plan side instead of from
the artifacts.

**The seam is asserted statically**, because behaviourally it is invisible: a
future edit making `evidence-mandate.ts` read the corpus itself would return
identical verdicts for every input the suite supplies, while silently adopting
the unsound direction. The test reads the module's own import list and requires
it to mention no `node:fs`, no `node:path`, no `readdirSync`, no `readFileSync`
and no `Bun.file`, with the extraction asserted non-empty first so a failed read
cannot pass vacuously. **#322's M11 is the precedent** — a behaviourally
equivalent mutation can only be killed statically.

### M5 is the whole return on the round

M5 deleted the Action line's invariant check outright —
`startsWith(HARD_FAILURE_ACTION_PREFIX)` became `startsWith("- Action:")` — and
**the suite stayed green.**

The negative fixture written specifically to pin that check *did* fail the
mutant, but **for the wrong reason**. Its Action line, `- Action: Fix and
re-run.`, is **shorter than the 36-character prefix**, so the surviving
`.slice(PREFIX.length)` ran off the end of the string and yielded `""` — which
the *blank-remainder* branch rejected regardless of whether the prefix was ever
compared.

> **A length accident was standing in for a content comparison, and every
> assertion in the test still read as though the comparison were pinned.**

The added fixture miscases one word (`Pipeline cannot CONTINUE.`) and keeps the
line long enough that the slice yields a non-blank remainder either way, so the
**only** thing that can reject it is a real comparison against the invariant.
The test now also asserts the line is longer than the prefix and its remainder
non-blank, **so the accident cannot come back silently.**

This is the class recorded in `docs/evidence/33-*.md` and re-hit in #315: **two
assertions that differ only in a way the code never reads are one assertion.**
Third occurrence in this lineage, and the second time it was found by a
mutation rather than by review.
