## How case counts were obtained, and a trap in doing so

Per-case counts come from `bun test -t <case name>`. **`-t` is a regex, not a
substring match.** The case names contain parentheses — `case 3 (P0,
CLAIM-243.2)` — and passing them unescaped makes `(P0, CLAIM-243.2)` a capture
group, so the filter matches nothing and reports:

```
0 pass  0 fail
```

which is indistinguishable at a glance from a suite that ran and found nothing
wrong. Every count above was taken with the parentheses escaped. This is the
same failure the handoff's `bun test -t "checkCommitPrefix"` note guards against
("must run 20 tests, not 0"), reached by a different route.
