## What shipped

One Story per feature row that has none, labelled and assigned. A run against a
fully populated milestone creates nothing, and reports that as the ordinary
outcome.

**The milestone document on disk is authoritative, not the forge's milestone
description.** That description is a truncated copy written by the previous
verb; a file in the working tree is re-readable, diffable and testable while a
description is not.

## The domain is not where Decision 2 points

Decision 2 fixes the authoritative input as the milestone document and the
identity key as the **feature-row description text**. But **no milestone
document has a domain column** — the table is `| Feature | Description |`.

The `domain:` label is declared on each Story block's own metadata line
(`docs/milestones/M2.md:29`), which is what `scripts/bootstrap-stories.py:119`
parses.

> **A skill that looked only at the feature table — which is where Decision 2
> points — would find no domain and be tempted to invent one.** The body names
> the right location explicitly, and says why the table is not it.

This was found while writing #42 and is recorded in **#307**.

The body reads that label **before** resolving the binding, and **mutation H1
confirms the ordering is checked**, not merely the presence.

The binding is validated **before anything is created**. A Story labelled with a
domain no later verb can resolve is a Story that stalls the pipeline *after* it
already exists — worse than failing in Phase 0, because the wrong artifact is
already in the tracker.

## The orphan report is the interesting half

A milestone may hold **a Story with no feature row**. Run against M1 today this
finds **five rows and six Stories**, because one Story was cut before the table
existed.

The skill **reports the orphan and creates nothing for it**. It does not delete
it, does not invent a feature row to match it, and does not renumber.

> A skill that papers over a real inconsistency between the milestone document
> and the issue tracker is worse than one that stops, **because the
> inconsistency is the finding**: the two sources disagree about what the
> milestone contains, and only a human knows which is right.

Reported in **both directions** — rows with no Story (which it creates), and
Stories with no row (which it never touches).

## The failure mode this skill is most exposed to

Called out in the body in terms: **a rate-limited *read* of the existing Stories
must never be treated as "no Stories exist".**

It is the worst case here specifically because it is **silent, plausible, and
multiplied by the row count** — absence is what the create step keys on, so one
throttled read duplicates every row at once. Every other skill in this Story has
the same shape of hazard against a single artifact; this one has it against N.
