# Milestone 6 — Trading pack

**Theme:** The greenfield, built safety-first — nothing reaches a market unattended.
**Estimate:** XL · **Stories:** 6 · **Depends on:** M2, M3, M5

LifeOS contributes no trading code, so every line here is new, and it is written
on the assumption that the agent will at some point be confidently wrong and
that this must cost nothing. The four-rung ladder is enforced in code rather
than convention: `PaperBroker` is the only adapter enabled out of the box,
thresholds are pre-registered before the first backtest, the risk officer is
spawned independently and holds an unappealable veto, and the live rung is the
last story of the milestone rather than the first.

## Milestone description

| Feature | Description |
|---------|-------------|
| Trade binding and the risk mandate | The `trade` DomainBinding with a strategy or position change as its unit of work, plus the committed risk mandate defining position limits, sector caps, portfolio heat, drawdown halt and permitted instruments, amendable only by a human-reviewed pull request. |
| Market data and broker adapter interfaces | Vendor-neutral provider interfaces for market data and brokerage, with PaperBroker as the default and only adapter enabled out of the box, and loud degradation to the research rung whenever a provider is absent rather than silent failure. |
| Backtest engine and pre-registration | Backtesting with metrics for CAGR, maximum drawdown, Sharpe, hit rate, exposure and turnover, gated by the pre-registration rule that thresholds, sizing and exits are written into the ISA before the first run, with a logged backtest counter to expose overfitting by iteration. |
| Risk officer, veto and kill switch | The risk-officer specialist spawned independently of the proposer, evaluating every order against the mandate, holding a veto that only the human principal may override with a logged reason, plus the armed kill switch that halts orders and demotes open trade Stories. |
| Trade journal and audit trail | The append-only orders log pinning each order to the SHA of the mandate that authorised it, the daily journal, and the post-mortem skill that closes the loop from thesis through outcome. |
| Live rung gating | The four-rung ladder enforced end to end, with the live rung requiring a written mandate, a per-order human authorisation, an armed kill switch, and a hard prohibition on any auto mode proceeding past the paper rung. |

## Stories

### S6.1 — Trade binding and the risk mandate

**Unit:** one binding surface or one mandate field group · **Size:** L · **Labels:** `type:story`, `domain:trade`, `class:private`, `rung:research`, `iai`

Ship the `trade` DomainBinding and make `USER/TRADING/MANDATE.md` the only
document in the system that grants permission to risk capital: parsed, pinned by
SHA, and amendable only by a human-merged pull request.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: The registry resolves `domain:trade` to `tradeBinding` with no edit
      under `packages/core`, and `defaultRung` is `research`; a Story created by
      `/iai:story-create` carries `rung:research` at creation.
- [ ] ISC-2: `checkRiskMandate` returns `VETO` when the mandate file is absent,
      unsigned, or past `expires_at`, naming the failing condition; asserted by
      three fixtures, with no grace period and no inferred extension.
- [ ] ISC-3: Every monetary field in the mandate is parsed as a string through
      one strict parser that throws on any value not matching the declared
      money pattern; a placeholder is a hard failure and never becomes `0`.
- [ ] ISC-4: `allowed_instruments` is a closed enum and anything absent is
      prohibited; a proposal naming options, futures, crypto, margin or shorting
      is refused against the default mandate.
- [ ] ISC-5: No agent code path writes to `MANDATE.md`; asserted by a test that
      greps the pack for writes to that path, plus a filesystem probe after a
      full fixture pipeline run.
- [ ] ISC-6: The mandate in force is identified by the short SHA of its commit,
      and the pipeline continues under the old SHA while an amendment PR is open
      and unmerged.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| `tradeBinding` object and registry entry | iai-domain-trade | `unitOfWork`, `verify` with four rungs, `gate`, `evidence`, `labels` |
| Mandate parser and strict money type | iai-domain-trade, iai-core | Strings throughout; `"—"` legal only as a declared placeholder |
| `checkRiskMandate` predicate | iai-core | Pure, under 50 ms, evaluates limits, caps, heat, drawdown, instruments |
| Mandate SHA pinning and amendment-PR path | iai-domain-trade | Agent may propose; only a human merges |
| Unit-of-work granularity rules | iai-domain-trade | One rebalance is one Task with N legs, never N Tasks |

**Verification:** Drive the mandate fixture set — valid, expired, unsigned,
absent, placeholder-bearing — through `checkRiskMandate` and assert the verdict
and the named condition for each, then confirm the write-probe finds no
agent-authored change to `MANDATE.md`.

### S6.2 — Market data and broker adapter interfaces

**Unit:** one provider interface · **Size:** M · **Labels:** `type:story`, `domain:trade`, `class:private`, `rung:research`, `iai`

Define `MarketDataProvider`, `BarSource`, `BrokerAdapter`, `MarketCalendar` and
`CorporateActions` so no vendor is hardcoded, ship `PaperBroker` as the sole
enabled adapter, and make every absence demote the rung loudly.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: In a default installation the enabled broker adapter set is exactly
      `["PaperBroker"]`; asserted by a test over the resolved configuration on a
      clean fixture home.
- [ ] ISC-2: Enabling a live adapter requires both an explicit configuration
      entry and a mandate permitting the instrument class; either alone leaves
      the adapter disabled.
- [ ] ISC-3: A missing provider demotes the Story's rung, posts a `## iai-risk`
      comment naming the integration, and applies `status:blocked`; asserted by
      a fixture run with the market-data provider removed.
- [ ] ISC-4: A quote whose `asOf` stamp is older than 60 s is treated exactly as
      an absent provider; asserted by a fixture provider returning a 61-second
      stamp.
- [ ] ISC-5: `BarSource` exposes a delisted-symbol channel, and a universe
      reporting zero delistings over a ten-year window is refused rather than
      silently backtested.
- [ ] ISC-6: Broker credentials are read from `.env` by code and never appear in
      a model context, an issue body, or an audit record; asserted by a scan of
      all fixture-run artifacts.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Provider interfaces and staleness stamps | iai-domain-trade | `quote()`, `bars()`, `universe()`, `asOf` on every response |
| `PaperBroker` implementation | iai-domain-trade | `submit()`, `cancel()`, `cancelAll()`, `positions()`, `mode: "paper"` |
| Absence and staleness degradation path | iai-domain-trade | Demote, comment, block — never silent |
| Session-start reconciliation | iai-domain-trade | Broker `positions()` versus `POSITIONS.yaml`; a mismatch blocks submission |

**Verification:** Run the pack against a fixture harness with each integration
removed in turn and assert the demotion, the `## iai-risk` comment and the
`status:blocked` label for every row of the integration table.

### S6.3 — Backtest engine and pre-registration

**Unit:** one metric or one bias audit · **Size:** L · **Labels:** `type:story`, `domain:trade`, `class:private`, `rung:backtest`, `iai`

Report behaviour as numbers rather than narrative, and make overfitting by
iteration visible: thresholds are committed before the first run, and every run
increments a counter nobody can reset.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: A backtest emits CAGR, maximum drawdown, Sharpe, hit rate,
      exposure, turnover and the worst five trades individually; a run missing
      any of these fails verification.
- [ ] ISC-2: `trade/backtest` refuses to run when the anchored `ISC-N` claims
      are uncommitted, or were modified after the previous run for this Story;
      asserted by a fixture that edits a threshold between runs.
- [ ] ISC-3: Every run increments `backtests_run` in the ISA frontmatter and
      appends a row to the run log; no code path decrements or resets it, and a
      test greps for any write that lowers the value.
- [ ] ISC-4: The look-ahead audit re-runs the strategy with all inputs shifted
      one bar and refuses promotion when the edge does not survive the shift.
- [ ] ISC-5: A post-hoc threshold change is written to the journal as a
      deviation, closes the current Story and opens a new one; the previous
      evidence artifact is retained, not deleted.
- [ ] ISC-6: The engine reaches no broker adapter; asserted by a test that runs
      a full backtest with every `BrokerAdapter` method stubbed to throw.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Metrics and equity/trade output | iai-domain-trade | `results.json`, `equity.csv`, `trades.csv` under `BACKTESTS/{slug}/` |
| Pre-registration enforcement | iai-domain-trade | Commit SHA of the ISA is the pre-registration timestamp |
| Backtest counter and run log | iai-domain-trade | Monotonic; visible to `iai-critic` and the human, forever |
| Look-ahead and survivorship audits | iai-domain-trade | Shift-one-bar re-run; delisted-symbol requirement |

**Verification:** Backtest the factor-sleeve fixture, assert every metric is
present and matches the golden file, then mutate a pre-registered threshold and
assert the second run is refused with the deviation path named.

### S6.4 — Risk officer, veto and kill switch

**Unit:** one risk axis or one halt path · **Size:** L · **Labels:** `type:story`, `domain:trade`, `class:private`, `rung:paper`, `iai`

Separate the proposer from the approver structurally, give the approver an
unappealable veto, and make the halt path something that has been exercised this
session rather than something that exists in code.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: `risk-officer` is spawned only by `iai-conductor`; a spawn attempt
      from `quant-analyst` is refused by `permission.task` on opencode and by
      the `PreToolUse` guard on Claude Code, and the refusal appears in the
      audit trail.
- [ ] ISC-2: `risk-officer` reads the proposal artifact and the book from disk;
      asserted by a test that supplies a poisoned analyst transcript and shows
      the verdict is unchanged.
- [ ] ISC-3: The verdict is one of `PASS`, `PASS_WITH_CONDITIONS`, `VETO`, is
      computed over position limits, correlation exposure, drawdown budget and
      mandate compliance, and `PASS_WITH_CONDITIONS` conditions are applied
      verbatim rather than paraphrased.
- [ ] ISC-4: A `VETO` cannot be cleared by any agent; it clears only when a
      human comment under `## iai-risk` and a journal override file both exist,
      and the recorded reason is non-empty. An override with no journal entry
      leaves `risk:vetoed` in place.
- [ ] ISC-5: `iai trade halt --all` cancels every open order, blocks new orders
      at the tool boundary for the session, demotes every open `domain:trade`
      Story to `rung:paper`, and writes the halt journal file — measured to
      complete within one tick in the fixture harness.
- [ ] ISC-6: "Armed" means a cancel-all probe was answered by the adapter this
      session; a session that has not probed reports the kill switch unverified
      and `autoDeny` fires.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| `risk-officer` agent spec and delegation rules | iai-agents, iai-core | Cross-vendor from the proposer; cannot propose |
| Four-axis evaluation | iai-domain-trade | Position limits, correlation clusters, drawdown headroom, mandate compliance |
| Veto state and human-override record | iai-domain-trade | `risk:vetoed`, `## iai-risk`, `JOURNAL/{date}-override.md` |
| Kill switch and arming probe | iai-domain-trade | Cancel-all, block, demote, record; auto-fires on drawdown breach and broker anomaly |

**Verification:** Run the separation-of-duties suite on both hosts, assert the
poisoned-transcript verdict is unchanged, then fire the kill switch against the
fixture broker and assert cancellation, demotion, block and journal entry within
one tick.

### S6.5 — Trade journal and audit trail

**Unit:** one record writer · **Size:** M · **Labels:** `type:story`, `domain:trade`, `class:private`, `rung:paper`, `iai`

Make the record answer "what were the rules when I bought this?" mechanically:
append-only `orders.jsonl` with `mandate_sha` on every line, a daily journal
written at entry, and a post-mortem that closes the loop from thesis to outcome.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: Every line in `ORDERS/{YYYY}/orders.jsonl` carries `mandate_sha`,
      and checking out that SHA reproduces the limits in force; asserted by a
      test that resolves the SHA and re-evaluates the order against it.
- [ ] ISC-2: The file is append-only: a partial fill appends a second line and
      never edits the first, and no code path rewrites, sorts, compacts or
      deletes a line; asserted by a mutation test over the writer.
- [ ] ISC-3: `authorised_by` is present on every line with `rung: "live"`; a
      line lacking it is reported as a corruption by the audit reader, not as a
      warning.
- [ ] ISC-4: The audit record is written by the guard at the enforcement point,
      not by the agent; asserted by a test in which the agent declines to log
      and the record appears anyway.
- [ ] ISC-5: No audit or journal record contains a credential or a raw
      `PRIVATE` value; asserted by a scan of the fixture run's full record set
      against the secret and account-number pattern list.
- [ ] ISC-6: `trade/journal --entry` refuses to write after an outcome for that
      position exists, so rationale cannot be reconstructed after the fact.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Append-only order writer | iai-domain-trade, iai-core | One shape shared with the other domains' audit trails |
| `POSITIONS.yaml` reader and reconciler | iai-domain-trade | Every position traces to the Story that authorised it; orphans block promotion |
| Daily journal and override records | iai-domain-trade | Rationale at entry, before the outcome is known |
| `trade/post-mortem` | iai-domain-trade | Thesis versus outcome, whether the invalidation trigger fired and was honoured |

**Verification:** Replay the worked-example order sequence including a partial
fill, diff `orders.jsonl` against the golden file, then run the mutation and
secret-scan tests over the produced records.

### S6.6 — Live rung gating

**Unit:** one gate condition · **Size:** L · **Labels:** `type:story`, `domain:trade`, `class:private`, `rung:live`, `iai`

Assemble the ladder end to end and close the last step: a written unexpired
mandate, a passing risk verdict, a kill switch armed this session, and one human
authorisation for one order. Do not start this story until S6.4 is closed.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: No code path reaches the broker's `submit()` at `rung:live` without
      a recorded per-order authorisation; asserted by a test that walks the call
      graph from every `submit()` call site back to an authorisation record and
      fails on any unguarded path.
- [ ] ISC-2: Authorisation is never batched, delegated, cached across orders, or
      inferred from approval of the parent Story; a twelve-leg fixture rotation
      requires twelve distinct authorisation records.
- [ ] ISC-3: `/iai:auto` is refused at dispatch against a `rung:live` Story,
      before any agent is spawned, with the hard-failure block emitted verbatim;
      asserted on both hosts.
- [ ] ISC-4: Each `autoDeny` condition — wrong rung, missing or expired mandate,
      notional over `maxPositionNotional`, unverified kill switch, market data
      staler than 60 s — independently refuses a live order; five fixtures, five
      refusals, each naming its condition.
- [ ] ISC-5: An unanswered gate never times out into approval; a fixture gate
      left pending for a simulated week remains `gate:pending` and the order is
      not submitted.
- [ ] ISC-6: `.env.live` is unreadable outside an armed session, and firing the
      kill switch makes it unreadable within the same process; asserted by a
      read probe before arming, after arming, and after the halt.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Rung ladder promotion and gate artifacts | iai-domain-trade | `gate:pending` at Task creation for any live-order Task |
| Per-order authorisation record | iai-domain-trade, both adapters | One order, one authorisation, one journal entry, one `orders.jsonl` line |
| `autoDeny` evaluation order | iai-core | `rung != live` first, so the common case denies cheaply |
| Auto-mode refusal and conditional credential loader | iai-core, iai-domain-trade | Hard rule in `checkRiskMandate`, not a setting |

**Verification:** Run the call-graph assertion, then drive the twelve-leg
fixture rotation and assert twelve authorisation records, five independent
`autoDeny` refusals, an `/iai:auto` refusal on both hosts, and an unreadable
`.env.live` before arming and after halt.

## Exit criteria

- [ ] No code path can reach a live order without a recorded per-order human
      authorisation and a passing `risk-officer` verdict; proven by the call
      graph assertion, not by inspection.
- [ ] `/iai:auto` refuses to advance a `rung:paper` Story past paper, and
      refuses a `rung:live` Story at dispatch, on both hosts.
- [ ] The kill switch halts within one tick, cancels open orders, demotes every
      open `domain:trade` Story to `rung:paper`, and un-arms live credentials.
- [ ] A default installation enables `PaperBroker` and nothing else, and can
      complete the ladder up to but not including `live`.
- [ ] Every line in `orders.jsonl` carries `mandate_sha`, and the file survives
      the append-only mutation test.
- [ ] A pre-registered threshold changed after a run closes the Story, opens a
      new one, and leaves the old evidence in place.
- [ ] `quant-analyst` cannot spawn, skip, summarise for, or filter inputs to
      `risk-officer` on either host.
- [ ] `bun test` green for `iai-domain-trade`; no trade-specific branch exists
      in `packages/core` or in any Tier-1 skill.

## Dependencies and sequencing

S6.1 is strictly first. The mandate type, the SHA pinning and the binding are
consumed by all five remaining stories, and starting S6.3 or S6.4 against a
provisional mandate schema guarantees rework in the risk path — the one place
rework is most expensive.

S6.2 and S6.3 run in parallel once S6.1 merges. The engine consumes `BarSource`
only through the interface, so agree that interface in S6.1's ISA and let the
two proceed independently; the delisted-symbol channel is the single coupling
point and belongs to S6.2.

S6.5 may start alongside S6.4 and must close before S6.6, because the live path
writes the records S6.5 defines. Writing the order log after the live path
exists means the first live-shaped order has nowhere correct to land.

**S6.6 is last and must not start until S6.4 is closed.** The live rung is
composed almost entirely of conditions the risk officer and the kill switch
supply: an unappealable veto, a verdict, and an arming probe answered this
session. Building the live path first would mean building it against stubs of
exactly the controls that make it safe, and a stubbed veto is not a veto. Treat
any pressure to reorder this pair as a signal to stop.
