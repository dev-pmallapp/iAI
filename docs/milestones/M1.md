# Milestone 1 — Kernel and foundation

**Theme:** The pure core everything sits on.
**Estimate:** L · **Stories:** 5 · **Depends on:** — (entry point)

Build the pure TypeScript kernel before anything can call it. Nothing in this
milestone imports a host, touches `process.cwd()`, or shells out; every module is
a function from input to a `Decision` that an adapter later applies. Get this
wrong and every later milestone inherits the mistake, so M1 also carries the
reconciliation pass that proves the design documents describe the three source
repositories rather than an invented version of them.

## Stories

### S1.1 — Monorepo scaffold and build targets

**Unit:** one build target or one CI check · **Size:** M · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Stand up the Bun workspace carrying all thirteen build targets from
ARCHITECTURE.md, wire the six CI checks that every later PR must pass, and
reconcile the design documents against their sources before anyone builds on
them.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-9.1: `bun install && bun run build` on a clean checkout exits 0 and
      produces an artifact for each of the ten `library` and `binary` targets
      named in ARCHITECTURE.md's Build Targets table.
- [ ] CLAIM-9.2: A pull request runs build, test, lint, typecheck, skill-lint
      and claim-lint as six separately reported required checks; failing any
      one leaves the PR unmergeable.
- [ ] CLAIM-9.3: A commit whose subject fails
      `^(#[0-9]+: .+|Merge .+|fixup! .+|squash! .+|Revert ".+")` is rejected by
      the commit-msg hook with a non-zero exit and the offending subject echoed.
- [ ] CLAIM-9.4: The lint rule set fails a file in `packages/core` that imports from
      either adapter package or calls `process.cwd()`.
- [ ] CLAIM-9.5: `skill-lint` fails a docs target whose frontmatter omits `name` or
      `description`, or whose `name` differs from its directory name.
- [ ] CLAIM-9.6: `docs/design/verification-pass.md` carries one row per assertion in
      `docs/design/` bearing exactly one of `confirmed`, `corrected`, `original`
      or `invented` against LifeOS, forge and oh-my-opencode. An `invented` row
      makes a source claim no source supports and names the commit that removed
      or corrected it; an `original` row is net-new design making no source
      claim, and needs no commit.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Bun workspace root, tsconfig project references, 13 package skeletons | iai-core | `docs` targets get a directory, not a build file |
| CI workflow with six required checks and both-host smoke install | iai-core | Both hosts installed from M1 per the drift risk row |
| Commit-msg hook wired to `checkCommitPrefix` | iai-core | `packages/core/src/guards`; regex from `03-workflow.md` |
| `SKILL.md` frontmatter linter | iai-references | Validates every file named `SKILL.md` against the host-intersection field set and string-only `metadata`; it does not sweep the docs targets |
| Design-claim reconciliation pass over `docs/design/` | iai-references | Reads the three source repositories; output is the CLAIM-9.6 table |

**Verification:** A clean clone runs `bun install && bun run build && bun test &&
bun run lint && bun run typecheck && bun run skill-lint` to completion; a
deliberately malformed commit and a deliberately malformed skill frontmatter are
each rejected; the reconciliation table is committed and every `invented` row is
closed by a commit.

### S1.2 — Data classification and the guard kernel

**Unit:** one pure module · **Size:** M · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Implement the four-level classifier, the single `Decision` type both adapters
map from, and the four guard predicates. This story lands the egress block before
any health, wealth or trade code exists, which is the whole point of its position
in the plan.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-15.1: `classify()` returns the highest class present in a mixed payload —
      a structure with four hundred public fields and one biomarker value
      classifies `PRIVATE` in its entirety.
- [ ] CLAIM-15.2: An unrecognised value classifies `PRIVATE`, and any path under
      `USER/` classifies at least `PRIVATE`, never `INTERNAL`.
- [ ] CLAIM-15.3: `checkEgress` returns `action: "block"` for a `SECRET` payload
      against every `Destination` including `locality: "on-device"`, and the
      returned `Decision` carries no `redacted` continuation.
- [ ] CLAIM-15.4: `checkEgress` blocks `PRIVATE` to a `cloud` destination with no
      per-session opt-in, and with the opt-in present returns `allow` carrying a
      de-identified `redacted` payload rather than the raw record.
- [ ] CLAIM-15.5: Each of `checkEgress`, `checkSpend`, `checkCommitPrefix` and
      `checkRiskMandate` returns in under 50ms at p99 over 10,000 iterations of
      the fixture corpus.
- [ ] CLAIM-15.6: No file under `packages/core/src/classify` or
      `packages/core/src/guards` performs I/O — the suite passes with `fs`, `net`
      and `process` stubbed to throw.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Four-level classifier and the highest-class-wins rule | iai-core | `packages/core/src/classify` |
| `Decision` type plus the two adapter mappings | iai-core | Exit code 2 and `throw` both derive from one object |
| `checkEgress` against the destination policy matrix | iai-core | `packages/core/src/guards`; redaction path included |
| `checkSpend`, `checkCommitPrefix`, `checkRiskMandate` | iai-core | `checkRiskMandate` refuses auto runs past the paper rung |
| Purity harness and latency benchmark | iai-core | Stubbed-runtime test plus the p99 measurement |

**Verification:** The purity harness passes with the runtime stubbed; the
benchmark report is committed to the evidence artifact; a hostile-input fixture
set drives every branch of the policy matrix and each returns the documented
action.

### S1.3 — GitHub operations layer

**Unit:** one `gh` operation family · **Size:** L · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Build every `gh` invocation iAI will ever make as a constructed argv plus a
parser for the response. The core decides what to run; only an adapter runs it,
which is what keeps the kernel testable without a network.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-21.1: Issues, milestones, sub-issues, labels, comments and PRs each have a
      constructor returning an argv array, and no file under
      `packages/core/src/gh` references `child_process`, `Bun.$` or `fetch`.
- [ ] CLAIM-21.2: Sub-issue creation emits the GraphQL mutation when the API is
      present, and on a simulated absence emits a task body containing the line
      `Parent: #901` plus a `## Tasks` checklist edit on the parent issue.
- [ ] CLAIM-21.3: A label transition emits exactly one `gh issue edit` carrying both
      `--add-label` and `--remove-label`, never two commands.
- [ ] CLAIM-21.4: A transition whose target label is already present emits zero
      commands and returns success.
- [ ] CLAIM-21.5: Given a `403` with `x-ratelimit-remaining: 0`, the backoff planner
      returns a resume plan naming the unprocessed items, and re-invoking with
      that plan emits commands for exactly those items.
- [ ] CLAIM-21.6: Every `gh` exit code in the taxonomy has a fixture and is classified
      retryable or fatal; an unmapped code is fatal, not retried.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Constructors for issues, milestones, labels and comments | iai-core | `packages/core/src/gh` |
| Sub-issue GraphQL path plus the `Parent: #N` fallback | iai-core | Fallback must produce an equivalent issue graph |
| PR construction including one `Closes #N` per line | iai-core | Comma-separated lists are rejected at construction |
| Response parsers, exit-code taxonomy, backoff and resume plans | iai-core | Feeds `references/gh-error-handling.md` in M2 |

**Verification:** Every constructor is covered by a golden-argv test; the
fallback path is exercised against a fixture with the GraphQL field removed; the
rate-limit fixture proves resume processes each item exactly once across two
invocations.

### S1.4 — Evidence and sentinel engine

**Unit:** one artifact surface · **Size:** M · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Implement the two-surface artifact model: a sentinel comment as the discovery
surface and a committed file as the durable store, joined by an SHA-pinned
permalink. This is how the pipeline reads its own history without a database.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-26.1: The producer emits the sentinel as the first line of the comment
      body, at column zero, unfenced, one per comment; the linter rejects each of
      those four violations with a distinct message.
- [ ] CLAIM-26.2: Given three `## iai-verdict` comments, the consumer returns the one
      with the newest `createdAt` and never merges or averages the others.
- [ ] CLAIM-26.3: Absence of a required sentinel returns a hard-failure `Decision`,
      never a default value.
- [ ] CLAIM-26.4: A 59,999-character artifact is inlined; a 60,001-character artifact
      yields a summary plus an SHA-pinned permalink; no emitted comment body
      exceeds 65,536 characters.
- [ ] CLAIM-26.5: Every permalink emitted matches `/blob/[0-9a-f]{7,40}/`; a
      branch-named link such as `blob/main/` fails the linter.
- [ ] CLAIM-26.6: Path templates interpolate `{issue}` and a `{ts}` in compact UTC
      ISO-8601 form (`20260825T141207Z`), and re-running the producer updates the
      existing sentinel comment instead of posting a second.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Sentinel namespace, producer rules and the sentinel linter | iai-core | `packages/core/src/evidence` |
| Consumer query with disambiguate-by-`createdAt` | iai-core | Newest wins; absence is a hard failure |
| 60,000-char budget, summary rendering, permalink pinning | iai-core | Headroom reserved for sentinel and metadata |
| Idempotent comment upsert keyed by sentinel | iai-core | Re-run safety for every M2 skill |

**Verification:** Boundary fixtures at 59,999 / 60,000 / 60,001 characters
produce the documented strategies; the linter rejects each malformed sentinel
shape; a double producer run leaves exactly one comment per sentinel.

### S1.5 — Domain binding interface and registry

**Unit:** one interface or registry rule · **Size:** S · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Declare `DomainBinding` and its four sub-specs, then build the registry that
resolves a `domain:*` label to a binding. Ship a `null` binding so the
conformance tests can prove the abstraction holds without any real domain
existing yet.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-31.1: `DomainBinding`, `UnitSpec`, `VerifySpec`, `GateSpec` and
      `EvidenceSpec` compile with every field name and type from
      `docs/design/01-skill-hierarchy.md`.
- [ ] CLAIM-31.2: Resolving a registered `domain:*` label returns that binding;
      resolving an unregistered one returns a hard failure naming the missing
      pack, never a default binding.
- [ ] CLAIM-31.3: A domain can be registered without editing any file under
      `packages/core/src` — the conformance suite registers `nullBinding` from a
      fixture package outside core and passes.
- [ ] CLAIM-31.4: The registry rejects a binding whose `verify.rungs[0].reversible` is
      `false` or whose `verify.evidenceRequired` is not `true`.
- [ ] CLAIM-31.5: The registry rejects a binding whose `evidence.sentinel` falls
      outside the `## iai-` namespace or whose `evidence.budgetChars` exceeds
      60,000.
- [ ] CLAIM-31.6: A search of `packages/core/src` for the literals `dev`, `trade`,
      `health`, `wealth` and `know` matches only the `id` union type and test
      fixtures.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| `DomainBinding` and sub-type declarations | iai-core | `packages/core/src/binding` |
| Registry, label resolution and failure modes | iai-core | Unregistered domain is a hard failure |

## Dependencies and sequencing

**Strictly ordered.** S1.1 lands first: nothing else has a workspace, a CI
signal or a lint rule until it does. S1.5 lands last within the milestone because
its `EvidenceSpec` validation rules depend on the budget and sentinel constants
from S1.4, and its `GateSpec` validation depends on the `Decision` shape from
S1.2.

**Parallel.** After S1.1 merges, S1.2, S1.3 and S1.4 are independent and can be
taken by three engineers. S1.6 is independent of all of them — it edits
documents, not code — but should land before M2 begins, because M2's reference
documents would otherwise be written in the retired vocabulary and need
migrating twice. They touch disjoint directories — `classify`/`guards`,
`gh`, and `evidence` — and share only the `Decision` type, which S1.2 defines
first and the other two import.

**Downstream.** M2 cannot begin its reference documents until S1.3 and S1.4 are
merged, because `references/gh-operations.md` and
`references/evidence-artifacts.md` document behaviour that must already exist
rather than behaviour someone intends to build.
