# Milestone 8 — Runtime and release

**Theme:** Get it onto two hosts, make the state visible, and prove nothing leaks.
**Estimate:** L · **Stories:** 3 · **Depends on:** M1, M2, M3, M4, M5, M6, M7

This milestone turns a monorepo into something a person installs. The installer
generates host-native agents and commands from one spec, merges configuration
without clobbering, and writes nothing without `--apply`. Pulse renders the state
and never writes it. Release engineering closes the loop: a leak scanner that
blocks merges, an audit of every irreversible action, both hosts smoke-tested,
and a v1.0 that ships zero telemetry.

## Stories

### S8.1 — Dual-host installer

**Unit:** one emitted artifact class · **Size:** L · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Emit agents and commands in both dialects from one `AgentSpec`, link the shared
skill tree rather than copying it, merge host configuration additively, and
print a full diff instead of writing unless `--apply` is passed.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: `iai install` without `--apply` writes zero bytes to disk and
      prints a complete diff of every intended change; asserted by a test that
      snapshots the fixture home's inode set and mtimes before and after.
- [ ] ISC-2: One `AgentSpec` emits a Claude Code agent carrying `name`, a
      comma-separated `tools` string and a model alias, and an opencode agent
      carrying no `name`, a qualified `provider/model-id` and a `permission`
      object; both validate against their host's schema.
- [ ] ISC-3: Emitted opencode `permission` blocks state `"*"` first and every
      specific denial after it, so the last matching rule is the denial;
      asserted by a lint pass over every emitted agent file.
- [ ] ISC-4: Merging into an `opencode.json` that already carries three
      unrelated plugins and a `mcp` block leaves all of them intact and adds
      exactly one entry; re-running produces a no-op with no duplicate entry.
- [ ] ISC-5: Existing hook registrations are merged, never replaced; a fixture
      `hooks.json` carrying a third-party `PreToolUse` entry retains it, and
      every overwritten file has a `<file>.iai-backup-<ts>` alongside it.
- [ ] ISC-6: Skills are installed to `.claude/skills/` only; `.opencode/skills/`
      is left empty, and both hosts resolve the same file — asserted by a
      discovery test run from a subdirectory of the fixture project.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Dry-run engine, diff renderer and `--apply` gate | iai-installer | Dry-run by default; every write backed up; `iai uninstall` removes only what the manifest claims |
| Agent and command emission per dialect | iai-installer | One body and union frontmatter for commands; `model` rewritten per host; `allowed-tools` declared for every shell injection |
| Config and hook merge | iai-installer | Additive, idempotent, never a whole-file rewrite |
| Skill linking and degradation notice | iai-installer | Prints exactly which opencode-only enhancements are unavailable on Claude Code |

**Verification:** Install into a clean fixture home for each of
`--host claude`, `--host opencode` and `--host both`, assert the dry run wrote
nothing, apply, re-apply and assert idempotence, then assert the pre-populated
config fixture retained every unrelated entry.

### S8.2 — Pulse read-only dashboard

**Unit:** one rendered surface · **Size:** M · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Ship the optional sidecar on `:31337` that renders GitHub state, the ISA tree
and the per-domain surfaces, holds no write capability at all, and whose absence
changes nothing about how iAI works.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: Pulse serves on `:31337` bound to loopback only; a connection
      attempt from a non-loopback interface in the fixture harness is refused.
- [ ] ISC-2: Pulse holds no write capability: it issues no `gh` mutation, opens
      no file for writing, and makes no non-`GET` HTTP request; asserted by a
      call-graph test plus a run under a read-only filesystem mount.
- [ ] ISC-3: With Pulse stopped, every skill and guard behaves identically and
      `/iai:status` returns the same state in text mode; asserted by running the
      full M4 fixture pipeline with the sidecar absent.
- [ ] ISC-4: Rendered surfaces cover GitHub state, the ISA tree and one surface
      per domain, and each is derived from disk and the GitHub API at request
      time with no cached store that can drift.
- [ ] ISC-5: No `PRIVATE` value crosses the Pulse boundary; a fixture private
      repo renders counts, labels, rungs and issue numbers, and renders no
      biomarker value, balance, position quantity or account number.
- [ ] ISC-6: Pulse is optional in packaging: a default install does not start
      it, and `iai install` succeeds and prints no warning on a host where port
      `31337` is already occupied.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Read-only server and loopback binding | iai-pulse | No write path exists; the guarantee is capability absence, not policy |
| GitHub and ISA-tree renderers | iai-pulse | Derived at request time from disk and the API; no second source of truth |
| Per-domain surfaces and redaction | iai-pulse | Reuses the core redaction table; counts and labels only for `class:private` |
| Absence-degradation tests | iai-pulse | `/iai:status` is the text-mode equivalent and must stay at parity |

**Verification:** Run the M4 fixture pipeline twice, once with Pulse running and
once without, assert identical outcomes, then run Pulse under a read-only mount
against the private fixture repo and assert no `PRIVATE` value appears in any
rendered response body.

### S8.3 — Release engineering and security audit

**Unit:** one audit control or one release gate · **Size:** L · **Labels:** `type:story`, `domain:dev`, `rung:compile`, `iai`

Close the milestone with the controls that make shipping safe: a leak scanner
that blocks merges, a row-by-row audit of the irreversible-action inventory,
compatibility testing on both hosts, the documentation set, and the v1.0 cut
with no telemetry in it.

**Acceptance criteria** (these seed the ISA claims):
- [ ] ISC-1: The leak scanner runs on every PR to the public repo against both
      the diff and the full tree, and fails the merge on any of: a regular file
      under `USER/`, a staged `.env*` in any directory, a secret pattern, an
      account-shaped digit run, a biomarker unit string outside `templates/` and
      fixtures, an impure template, or a `USER/` symlink that is missing or not
      gitignored. Seven seeded fixtures, seven blocks.
- [ ] ISC-2: A leak finding is a hard block with no warn-and-continue path;
      asserted by a test that seeds a finding and shows the workflow exits
      non-zero with no bypass flag available.
- [ ] ISC-3: Every row of the irreversible-action inventory — dev, trade,
      health, wealth, know and iAI itself — has a passing test proving its
      guard, its authoriser and its kill switch or its capability absence; a
      row without a test fails the audit.
- [ ] ISC-4: The full dev-domain fixture milestone runs to a merged integration
      PR on a clean machine on both Claude Code and opencode, with human action
      limited to the three gates and the merge.
- [ ] ISC-5: The shipped artifact emits zero telemetry: no network call is made
      by the plugin, the installer or Pulse to any endpoint the user did not
      configure; asserted by a full fixture run under a deny-all egress proxy
      that fails on any unexpected connection.
- [ ] ISC-6: `README.md`, `ARCHITECTURE.md`, `CONTRIBUTING.md` and every
      `docs/design/` claim reconcile against the shipped code; the build-target
      table and the commands table both parse and every target named in them
      exists.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Leak scanner and CI wiring | iai-core | Diff and full tree; hard block, never a warning |
| Irreversible-action audit suite | iai-core | One test per row of the inventory; adding a domain adds a row and a test |
| Both-host compatibility run | iai-installer, both adapters | Clean machine, clean fixture repo, milestone to merged integration PR |
| Docs reconciliation and the v1.0 cut | iai-references | Zero telemetry asserted under a deny-all proxy before the tag |

**Verification:** Run the seeded leak-scanner fixtures and assert seven blocks,
run the irreversible-action suite and assert one passing test per inventory row,
then execute the clean-machine install and full fixture milestone on both hosts
under the deny-all egress proxy.

## Exit criteria

- [ ] A clean machine installs iAI on Claude Code and on opencode and completes
      one full dev-domain milestone, with human action limited to the three
      gates and the merge.
- [ ] The leak scanner passes on the release commit and blocks on all seven
      seeded findings.
- [ ] Zero telemetry ships: a full run under a deny-all egress proxy makes no
      unconfigured network call from the plugin, the installer or Pulse.
- [ ] `iai install` writes nothing without `--apply`, backs up every file it
      overwrites, and is idempotent on re-run.
- [ ] Every existing hook registration and unrelated config entry in the fixture
      home survives installation intact.
- [ ] Pulse never writes, and every skill and guard behaves identically with the
      sidecar absent.
- [ ] Every row of the irreversible-action inventory has a passing test for its
      guard, authoriser and kill switch or capability absence.
- [ ] `bun test`, `typecheck`, `lint` and `skill-lint` green across all thirteen
      build targets; v1.0 tagged.

## Dependencies and sequencing

S8.1 and S8.2 are parallel and share nothing but the fixture home. The installer
emits files; Pulse reads state. Assign them separately and expect no merge
conflicts.

S8.3 is gated on both. Its compatibility criterion installs what S8.1 emits, and
its telemetry criterion has to cover Pulse's network behaviour, so a green audit
before either lands is measuring an incomplete system. Start the leak scanner and
the irreversible-action suite early — both are independent of the other two
stories and are the longest-lead items — but hold the v1.0 cut until S8.1 and
S8.2 are closed.

The whole milestone depends on every preceding one, and the dependency is real
rather than nominal: the irreversible-action audit enumerates the trade kill
switch from M6, the clinician boundary from M5, the money prohibition and the
canon gate from M7, and the merge boundary from M4. If any of those rows has no
implementation to test, the audit cannot pass and v1.0 cannot be cut.
