# Milestone 7 — Wealth and Knowledge

**Theme:** The two supporting packs — the balance sheet and the citation backbone.
**Estimate:** M · **Stories:** 2 · **Depends on:** M2, M3

Neither pack is the star of the system and both are load-bearing for the ones
that are: `wealth` is the financial state of record and refuses to act, and
`know` is where every other domain's claims resolve to a source. They share a
shape — mostly bookkeeping, both refusing to move anything, both failing quietly
rather than loudly if you let them — so both stories below spend their
acceptance criteria on making the quiet failures loud.

## Stories

### S7.1 — Wealth pack

**Unit:** one schema object type, one leaf skill, or one validation rule · **Size:** M · **Labels:** `type:story`, `domain:wealth`, `class:private`, `rung:recorded`, `iai`

Bind the balance sheet to the universal loop over LifeOS's nine-type FINANCES
schema, reconcile to the cent, and make "iAI never moves money" a matter of
capability absence rather than a refusal the model can be argued out of.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-162.1: All nine FINANCES object types — `overview`, `income_source`,
      `expense`, `investment_account`, `account`, `goal`, `tax_profile`,
      `obligation`, `vendor` — validate against `schema.yaml` with their
      declared enums, and an out-of-enum value is rejected naming the field and
      the permitted set.
- [ ] CLAIM-162.2: Every monetary field is a string parsed through one strict
      function; a placeholder such as `"$X,XXX"` is a hard failure on any
      arithmetic path and never coerces to `0`; asserted by a fixture ledger
      containing placeholders in three object types.
- [ ] CLAIM-162.3: `last_4` is exactly four characters with leading zeros preserved,
      dates are ISO 8601, and no artifact produced by the pack contains a full
      account number; asserted by a pattern scan over a complete fixture run.
- [ ] CLAIM-162.4: `wealth/reconcile` closes a period only when the closing-balance
      difference is exactly `0.00` with every unmatched line carrying a written
      explanation; a fixture with a one-cent residual and no explanation fails
      to promote to `rung:reconciled`.
- [ ] CLAIM-162.5: No code path in the pack authenticates to a bank or brokerage, or
      initiates a transfer, payment or trade; asserted by a call-graph test over
      the pack plus an `autoDeny` fixture for each of the five deny conditions.
- [ ] CLAIM-162.6: `wealth/cashflow` refuses fewer than three reconciled periods, and
      `wealth/net-worth` reports the trade pack's investment line as stale with
      its `as_of` date rather than extrapolating; the pack reads nothing under
      `USER/TRADING/`.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| `wealthBinding`, schema loader and validation rules | iai-domain-wealth | Nine object types; `schema.yaml` is the authority, markdown files are renderings |
| Reconciliation and statement import | iai-domain-wealth | Content-hash per line for idempotent re-import; `vendors.yaml` substring matching, never model-guessed |
| Cashflow, obligation audit and tax-prep | iai-domain-wealth | `obligation-audit` reports price creep and cancellation windows; `tax-prep` assembles and never opines |
| Net-worth, goal-track and the spend gate | iai-domain-wealth | Consumes the trade pack's published account valuation through a declared interface only |

**Verification:** Run the reconciliation fixture set — clean period, explained
residual, unexplained residual, duplicate re-import, mixed currency, `last_4`
collision — and assert the verdict for each, then run the call-graph test
proving no credentialed write path to any institution exists.

### S7.2 — Knowledge pack

**Unit:** one source, one claim, or one retrieval path · **Size:** M · **Labels:** `type:story`, `domain:know`, `rung:captured`, `iai`

Build Cortex-lite as the citation backbone: snapshot at capture, distil
falsifiable claims with locators, retrieve with BM25 over the filesystem, and
make a contradiction with canon open a resolution Story instead of overwriting
it.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-167.1: `know/capture` writes to `MEMORY/KNOWLEDGE/{People,Companies,
      Ideas,Research}/{slug}.md` with `url`, `author`, `retrieved_at` and
      `sha256` recorded, and the snapshot text present on disk; a claim remains
      verifiable after the live URL is made to 404 in the fixture harness.
- [ ] CLAIM-167.2: The external-content fence is applied at write time by
      `know/capture`, so the fence is on disk before any model reads the file;
      asserted by a fixture page containing `Ignore previous instructions` and a
      forged `[END EXTERNAL CONTENT]` marker.
- [ ] CLAIM-167.3: Retrieval is BM25 computed on demand from `MEMORY/KNOWLEDGE/**`
      with no vector database and no persisted index; asserted by a test that
      greps the pack's dependency tree for embedding and vector-store packages
      and by deleting every derived file and re-querying successfully.
- [ ] CLAIM-167.4: A `CONFLICT(tier-A)` verdict opens a `domain:know` resolution
      Story, labels both entries `know:conflict`, and blocks promotion until
      that Story closes; the existing canon entry is not modified in the same
      run.
- [ ] CLAIM-167.5: Promotion is refused when the contradiction check ran against a
      corpus SHA that has since moved, when a source's `sha256` does not match
      its snapshot, or when a claim cites a source that itself cites nothing;
      three fixtures, three refusals.
- [ ] CLAIM-167.6: `promoted` appears in frontmatter only after a human `**Decision:**
      APPROVED` comment; tier B is citable only with its confidence attached and
      tier C is not citable outside `domain:know`, enforced at `story-design`.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| `knowBinding`, frontmatter schema and tiering | iai-domain-know | Type is data, tier is permission; `A`/`B`/`C` |
| Capture, snapshotting and the fence | iai-domain-know | SSRF blocklist, size cap, timeout, redirect cap, re-check after every redirect |
| Distil, cross-link and BM25 retrieval | iai-domain-know | Locators into the snapshot; wikilink resolution checked at `cross-linked` and by `digest` |
| Contradiction check and the resolution Story | iai-domain-know | `CLEAR` / `CONFLICT(tier-A)` / `TENSION`; corpus SHA recorded per run |

**Verification:** Capture the four-source ApoB fixture corpus, distil the
discordance claim, run `know/contradict` against a seeded tier-A conflict and a
tier-C tension, and assert a resolution Story for the former, a recorded note
for the latter, and a blocked promotion until the Story closes.

## Exit criteria

- [ ] A trade thesis and a health protocol both resolve their citations through
      the knowledge pack, with each citation pinned by SHA permalink to a
      snapshot on disk.
- [ ] A contradicting claim opens a resolution Story rather than overwriting
      canon, and both entries carry `know:conflict` until it closes.
- [ ] A reconciliation closes only at a difference of exactly `0.00`, with every
      unmatched line explained in writing.
- [ ] No code path in `iai-domain-wealth` authenticates to, or initiates a
      transfer at, any financial institution.
- [ ] A monetary placeholder is a hard failure on every arithmetic path, and no
      full account number appears in any artifact.
- [ ] Retrieval works with every derived file deleted, and the dependency scan
      finds no vector database.
- [ ] Hostile-input tests pass for `know/capture`: injected instructions, a
      forged fence terminator, a link-local redirect, an oversized response and
      malformed UTF-8.
- [ ] `bun test` green for `iai-domain-wealth` and `iai-domain-know`; neither
      pack imports the other, or any other pack.

## Dependencies and sequencing

These two stories are independent and fully parallel. They share no types, no
files and no build target: `wealth` writes under `USER/FINANCES/`, `know` writes
under `MEMORY/KNOWLEDGE/`, and the packs-never-import-packs rule forbids the one
edge that might otherwise couple them. Assign them to two engineers and expect no
integration work between them.

The only cross-pack contract in the milestone is `wealth`'s consumption of the
trade pack's published account-level valuation, and it is one field read through
a declared interface. Stub it if M6 has not landed — the wealth pack must report
that line as stale with its `as_of` date anyway, so the stub exercises the code
path that matters.

`know` is on the critical path for M6 and M5 in one direction only: a thesis or a
protocol that cites a missing entry is a hard failure at `story-design`. If those
milestones are running concurrently, land S7.2's capture and cite skills early so
their Designs have somewhere to point.
