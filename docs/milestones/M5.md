# Milestone 5 — Health pack

**Theme:** Advisory only — observe, trend, flag, hand to a clinician, stop.
**Estimate:** L · **Stories:** 5 · **Depends on:** M2, M3

This milestone binds biometrics and labs to the universal loop without ever
acquiring medical authority. Every rung is deterministic arithmetic over
structured data on local disk, the terminal artifact is a brief containing
questions and no instructions, and the emergency classifier is a pure predicate
that halts the pipeline before any model is consulted. Build it in the order
below: ingestion first, because every later story reads the types it defines.

## Milestone description

<!-- This block is pasted verbatim into the GitHub milestone description.
     /iai:story-create parses the table below: one row becomes one Story. -->

| Feature | Description |
|---------|-------------|
| Biometric ingestion adapters | The healthsync layer ported from LifeOS: Oura, Eight Sleep, Apple Health, Function Health labs and Health Auto Export, writing timezone-resolved day files with per-source status so a stale source can never silently report healthy. |
| Health binding and rungs | The `health` DomainBinding with a protocol or tracked marker as its unit of work, and the observe, trend, flag and clinician-review rungs, where nothing promotes past clinician-review automatically. |
| Trend and anomaly engine | Trend computation over pre-declared windows with per-result reference ranges stored alongside each value, so an assay change mid-series cannot corrupt the trend, plus anomaly flagging against those ranges rather than against a global constant. |
| Clinician brief and emergency short-circuit | Generation of a locally-rendered clinician brief containing observations, trends and questions but never conclusions, and the emergency classifier that short-circuits the entire pipeline and instructs the user to seek immediate care. |
| Health privacy enforcement | All health data classified `class:private`, trend and flag computation performed locally on structured data, and only derived de-identified summaries permitted to reach a cloud model, and then only on an explicit per-session opt-in. |

## Stories

### S5.1 — Biometric ingestion adapters

**Unit:** one source adapter · **Size:** L · **Labels:** `type:story`, `domain:health`, `class:private`, `rung:observe`, `iai`

Port LifeOS's healthsync layer as five adapters behind one contract, writing
timezone-resolved day files and lab files with a per-source status that is
computed from freshness rather than from the last HTTP result.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-105.1: Each of `oura`, `eightsleep`, `apple`, `function` and `hae`
      exports a fetch function whose return value validates against the
      declared `DayFile` or `LabsFile` type; asserted by one schema test per
      adapter over a recorded fixture response.
- [ ] CLAIM-105.2: `SourceStatus` resolves to exactly one of `ok`, `stale`, `failed`,
      `unconfigured`, `awaiting-first-export`, computed from `fetched_at`
      against a per-source expected cadence; a fixture whose last fetch
      succeeded 21 days ago reports `stale` and never `ok`.
- [ ] CLAIM-105.3: Day-boundary resolution follows `LIFEOS_HEALTH_TZ` → `TZ` → host →
      fallback with first hit winning, and the winning level is recorded in
      `DayFile.metrics`; asserted by four tests, one per level.
- [ ] CLAIM-105.4: Running `health/ingest` twice for the same resolved local date
      leaves exactly one day file for that date with byte-identical content;
      asserted by a double-run test that diffs the tree.
- [ ] CLAIM-105.5: A `LabsFile` write is rejected when any `Biomarker` in it lacks
      `ref_low` or `ref_high`; asserted by a fixture panel carrying one
      range-less result.
- [ ] CLAIM-105.6: `CurrentJson.sources` carries an entry for every configured
      `SourceName`, and an unconfigured source appears as `unconfigured` rather
      than being omitted from the map.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Adapter contract and shared types | iai-domain-health | `SourceName`, `SourceStatus`, `DayFile`, `Biomarker`, `LabsFile`, `LastNight`, `CurrentJson`, reused verbatim from LifeOS |
| Wearable adapters: `oura`, `eightsleep` | iai-domain-health | Sleep stages, readiness, HRV, RHR, bed temperature into `LastNight` |
| Apple bridge and `hae` fallback | iai-domain-health | `awaiting-first-export` is a first-class state, distinct from `failed` |
| Function Health labs adapter | iai-domain-health | Panels become `Biomarker[]` with per-result `ref_low`/`ref_high` |
| Timezone resolver and idempotent day-file writer | iai-domain-health | Records the resolution level used; re-run overwrites per resolved date |

**Verification:** Run all five adapters against recorded fixtures with the
network denied, diff the emitted `USER/HEALTH/DATA/` and `USER/HEALTH/LABS/`
trees against golden files, then re-run and assert the tree is unchanged.

### S5.2 — Health binding and rungs

**Unit:** one binding surface · **Size:** M · **Labels:** `type:story`, `domain:health`, `class:private`, `rung:observe`, `iai`

Ship the `health` DomainBinding so the Tier-1 verbs execute the health loop
with no health-specific branch anywhere in core, and enforce the four-rung
ladder that terminates at `clinician-review`.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-111.1: The registry resolves the `domain:health` label to
      `healthBinding` with no edit to any file under `packages/core`; asserted
      by a test that fails if `git diff --stat` for the story branch touches
      `packages/core/src/binding`.
- [ ] CLAIM-111.2: `defaultRung` is `observe`, and a Story created by
      `/iai:story-create` on a health milestone carries `rung:observe` at
      creation.
- [ ] CLAIM-111.3: Each rung's `entryCriteria` is evaluated as a predicate over disk
      state; a fixture failing any single criterion is refused with that
      criterion named in the message, for all four rungs.
- [ ] CLAIM-111.4: No code path promotes a Story off `rung:clinician-review`;
      asserted by a test that enumerates every promotion transition in the
      binding and requires the `clinician-review` successor set to be empty.
- [ ] CLAIM-111.5: `unitOfWork` accepts one marker's measurement-trend-review chain
      as a single Task and rejects both a bare measurement (below `minSize`)
      and a four-marker Task (above `maxSize`) with the reason stated.
- [ ] CLAIM-111.6: `/iai:init` creates the five health labels plus `class:private`
      with the declared hex colours and reconciles a drifted colour on re-run
      without recreating the label.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| `healthBinding` object and registry entry | iai-domain-health | `unitOfWork`, `verify`, `gate`, `evidence`, `labels` |
| Rung ladder and entry-criteria predicates | iai-domain-health | Tool-checked for `observe`/`trend`, model-judged for `flag`, human-attested for `clinician-review` |
| Unit-of-work sizing rules | iai-domain-health | Drives `/iai:size` and `/iai:replan` for markers and protocols |
| Label set and `/iai:init` reconciliation | iai-domain-health | `rung:*`, `health:emergency`, `class:private` |

**Verification:** Run the M1 binding conformance suite against `healthBinding`,
then drive a fixture Story through `observe → trend → flag` and assert the
promotion attempt off `clinician-review` is refused.

### S5.3 — Trend and anomaly engine

**Unit:** one computation over a marker series · **Size:** L · **Labels:** `type:story`, `domain:health`, `class:private`, `rung:observe`, `iai`

Compute longitudinal movement over windows declared before the first data
point, and flag out-of-band values against each result's own reference range so
a vendor or assay change cannot corrupt a five-year series.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-116.1: `health/trend` refuses a window whose Design declaration mtime is
      later than the `collected_at` of the first point in the series, naming
      both timestamps in the refusal.
- [ ] CLAIM-116.2: Every anomaly decision compares a value against that result's own
      `ref_low`/`ref_high`; asserted by a fixture series whose range changes
      mid-series, in which no historic result is reclassified and an explicit
      `assay-change` note is emitted at the boundary.
- [ ] CLAIM-116.3: A window with more than 10% missing days fails the `observe` entry
      criterion, and no interpolated or carried-forward value appears in any
      output; asserted by a fixture with 11 of 90 days absent.
- [ ] CLAIM-116.4: A single out-of-range value with no prior series produces no flag;
      a flag requires the crossing to persist across at least two consecutive
      measurements.
- [ ] CLAIM-116.5: A change of device identity recorded in `DayFile.metrics` splits
      the series, and `health/trend` refuses to span the boundary unless
      `--allow-device-change` is passed.
- [ ] CLAIM-116.6: No trend or anomaly code path invokes a model; asserted by a test
      that runs the engine with every model client stubbed to throw.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Series assembly and missingness accounting | iai-domain-health | Reports `n` and missing-day count alongside every trend; never imputes |
| Pre-declared window and threshold enforcement | iai-domain-health | Reads the declaration from the Design on disk, not from conversation |
| Per-result range comparison and assay-change detection | iai-domain-health | Powers `health/lab-review` deltas |
| Persistence rule and device-segmentation | iai-domain-health | Two consecutive crossings minimum; firmware change breaks the series |

**Verification:** Golden-file the trend and anomaly output for the ApoB,
hs-CRP and RHR fixture series, including the assay-change and device-change
cases, and assert the model-stub test passes.

### S5.4 — Clinician brief and emergency short-circuit

**Unit:** one gated output path · **Size:** L · **Labels:** `type:story`, `domain:health`, `class:private`, `rung:observe`, `iai`

Generate the brief locally as observations, trends and numbered questions, and
put the emergency classifier in front of the whole pipeline so an acute signal
never becomes a chart.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-121.1: The emergency predicate is pure, deterministic and runs before any
      trend, flag or brief work in `health/anomaly`; asserted by a test that
      injects an emergency fixture and requires zero trend, flag or brief
      artifacts on disk afterwards.
- [ ] CLAIM-121.2: Every row in the emergency column of the anomaly table has a
      fixture that halts the pipeline, applies `health:emergency`, and emits
      the fixed notice byte-for-byte from the guard.
- [ ] CLAIM-121.3: The halted pipeline does not resume until a human comment clears
      `health:emergency`; a re-run against an uncleared fixture halts again
      with the same notice.
- [ ] CLAIM-121.4: A brief containing an imperative sentence or a prescription noun
      is blocked before write; the blocked text is discarded and does not
      appear in the brief, in any comment, or in any log.
- [ ] CLAIM-121.5: A committed brief contains zero imperative sentences and at least
      one numbered question; asserted by the brief linter over the worked
      example fixture.
- [ ] CLAIM-121.6: No skill writes to `USER/HEALTH/CONDITIONS.md`; asserted by a test
      that greps the pack for writes to that path and by a filesystem probe
      after a full fixture run.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Emergency predicate and fixed notice | iai-core, iai-domain-health | Guard-authored text; the model cannot paraphrase or soften it |
| Brief renderer, local only | iai-domain-health | Window, series, adherence, confounders, numbered questions |
| Imperative and prescription linter | iai-domain-health | Holds and discards; never surfaces the blocked text with a warning |
| Clinician-boundary gate wiring | iai-domain-health | `gate:pending` label, `## iai-gate` sentinel, host permission block |

**Verification:** Run the full emergency fixture table and assert a halt on
every row, then generate the worked-example brief and assert the linter reports
zero imperatives and one blocked-and-regenerated sentence.

### S5.5 — Health privacy enforcement

**Unit:** one egress path · **Size:** M · **Labels:** `type:story`, `domain:health`, `class:private`, `rung:observe`, `iai`

Make the leak impossible rather than discouraged: label every health issue
`class:private` at creation, compute locally, and permit only de-identified
derived summaries outward, and only after an explicit per-session opt-in.

**Acceptance criteria** (these seed the Design claims):
- [ ] CLAIM-126.1: Every Story and Task created in `domain:health` carries
      `class:private` at creation, and no skill code path removes it; asserted
      by a test that greps the pack for `--remove-label "class:private"` and by
      a live label check on a fixture issue.
- [ ] CLAIM-126.2: `checkEgress` returns `block` for a raw `Biomarker` or `DayFile`
      payload to any `locality: "cloud"` destination with no session opt-in
      recorded; asserted for both hosts against the same core predicate.
- [ ] CLAIM-126.3: With the opt-in recorded, the same payload egresses only as the
      de-identified projection — marker name, `n`, window, delta, direction —
      with `collected_at`, provider name and raw value absent.
- [ ] CLAIM-126.4: The opt-in does not survive the session and cannot be set from any
      config file; asserted by a test that writes the consent key into every
      config layer and shows `checkEgress` still blocks.
- [ ] CLAIM-126.5: The egress guard completes in under 50 ms at the 99th percentile
      over a 1000-payload benchmark and performs no I/O.
- [ ] CLAIM-126.6: A blocked egress writes an append-only audit record carrying the
      issue, actor, action and decision, and carrying no raw biomarker value.

**Indicative tasks:**
| Task | Build target | Notes |
|------|--------------|-------|
| Health payload classifier | iai-core | Mixed payloads take the highest class present; unknown is `PRIVATE` |
| De-identified projection | iai-domain-health | The only shape eligible to leave the machine |
| Per-session opt-in state | iai-core, both adapters | Snapshot handed to the guard; never looked up inside it |
| Egress conformance tests, both hosts | iai-adapter-claude, iai-adapter-opencode | Exit 2 on one side, `throw` on the other, one predicate |

**Verification:** Run the egress conformance suite on both hosts with a raw
biomarker payload and assert a block with no opt-in, a projection with an
opt-in, and a block again in a fresh session.

## Exit criteria

- [ ] A test proves raw biomarker values cannot reach a cloud model without an
      explicit per-session opt-in, on both Claude Code and opencode.
- [ ] The emergency classifier halts the pipeline on every fixture in the
      emergency column of the anomaly table, with no trend, flag or brief
      produced.
- [ ] All five ingestion adapters run against fixtures with the network denied
      and produce byte-identical output on re-run.
- [ ] A source that stopped reporting reports `stale`, and `/iai:status`
      surfaces every non-`ok` source before any rung is evaluated.
- [ ] A mid-series reference-range change leaves every historic result
      correctly classified and emits an `assay-change` note.
- [ ] No promotion path exists off `rung:clinician-review`, in any
      configuration.
- [ ] A committed clinician brief contains zero imperative sentences.
- [ ] `bun test` green for `iai-domain-health`; no health-specific branch
      exists in `packages/core` or in any Tier-1 skill.

## Dependencies and sequencing

Start S5.1 alone. Every other story consumes `Biomarker`, `DayFile` and
`SourceStatus`, so shipping those types late forces rework in three places.

S5.2 and S5.3 may run in parallel once S5.1's types are merged: the binding is
label and lifecycle work, the engine is arithmetic, and they meet only at the
rung entry criteria. Agree that interface in S5.2's Design before either starts.

S5.4 must not start until S5.3 is closed. The brief renders trends, and the
emergency predicate must run in front of an engine that already exists,
otherwise "runs first" cannot be tested.

S5.5 may start any time after S5.2 supplies the label set, but it must close
last: its conformance suite exercises payloads produced by S5.1, S5.3 and S5.4,
and a green run before those exist proves nothing. M6 depends on this milestone
only for the shared `class:private` egress machinery, so S5.5's landing is the
signal that unblocks trading work.
